# 固定版本源码定位

本题使用 Go 1.27.1 和 Gin v1.12.0。下面链接指向固定 tag；本地执行证据另外记录实际读取文件的 SHA256。官方网页可能更新排版，优先按符号定位，不背易漂移的行号。

## Go：从网络到处理器

- [net/http/server.go @go1.27.1](https://github.com/golang/go/blob/go1.27.1/src/net/http/server.go)：conn.serve、serverHandler.ServeHTTP、ServeMux.ServeHTTP、Server.Shutdown。先找 ServeHTTP 调用边界，再读 Shutdown 的连接管理。handler 返回后的 ResponseWriter 不应继续由业务 goroutine 使用
- [net/http/request.go @go1.27.1](https://github.com/golang/go/blob/go1.27.1/src/net/http/request.go)：Request.Context/WithContext、MaxBytesReader；观察取消由连接关闭/请求取消/handler返回等生命周期触发，MaxBytesReader 的上限错误并非业务校验
- [context/context.go @go1.27.1](https://github.com/golang/go/blob/go1.27.1/src/context/context.go)：WithTimeout、WithDeadline、cancelCtx；观察 Done、Err 与父子传播，cancel不会强制终止任意函数
- [encoding/json/stream.go @go1.27.1](https://github.com/golang/go/blob/go1.27.1/src/encoding/json/stream.go)：Decoder.Decode 每次读取一个值，EOF检查是本题应用策略
- [HTTP 官方 API](https://pkg.go.dev/net/http@go1.27.1)、[Context 官方 API](https://pkg.go.dev/context@go1.27.1)：区分方法合同和本题选择的状态码映射

## 应用代码并不等于框架源码

从本题 NewHandler 跟到 CreateHandler/RegisterOrders，再看 Store 接口；超时预算从解码后开始、503/504/422错误映射、SKU规范化、256字节上限都由应用定义，不是 Go/Gin 自动替每个项目选好的企业标准。本地重放记录来源于本题测试，不是对线上负载或数据库行为的证明。

## Gin：从 Engine 到绑定

- [go.mod @v1.12.0](https://github.com/gin-gonic/gin/blob/v1.12.0/go.mod)：最低 Go 1.25.0；本题通过固定的 Go1.27.1运行，不自动升级
- [gin.go @v1.12.0](https://github.com/gin-gonic/gin/blob/v1.12.0/gin.go)：Engine.ServeHTTP 从池取 Context、绑定 Request/Writer、进入 handleHTTPRequest，结束后归还池。读到池化后解释为什么不能长期保存原 Context
- [context.go @v1.12.0](https://github.com/gin-gonic/gin/blob/v1.12.0/context.go)：Next 推進索引执行余下链；Abort 使后续链停止，不等于从当前函数 return；ShouldBindWith 调用具体 binder 并返回 error
- [binding/json.go @v1.12.0](https://github.com/gin-gonic/gin/blob/v1.12.0/binding/json.go)：decodeJSON 的解码与 validate 顺序；它不包含本题第二次 Decode 的 EOF 合同，StrictJSON 是显式扩展
- [response_writer.go @v1.12.0](https://github.com/gin-gonic/gin/blob/v1.12.0/response_writer.go)：Written/WriteHeaderNow，配合 committed_response_not_overwritten 理解已提交响应
- [官方绑定文档](https://gin-gonic.com/en/docs/binding/binding-and-validation/)、[官方错误中间件示例](https://gin-gonic.com/en/docs/middleware/error-handling-middleware/)：本课借助其 API 思路，但额外要求错误脱敏及 Written 守卫；不原样暴露 err.Error()

源码阅读练习：画出 ErrorEnvelope.Next → Recovery.Next → gate.Next → route 返回 → 各中间件回卷，并用 next_unwinds 测试核对。路由树、HTTP/3和底层连接复用的完整源码分析是后续主题，不在本题完成声明内。

## 无真实时间竞态的后置deadline测试

[testing/synctest @go1.27.1](https://github.com/golang/go/blob/go1.27.1/src/testing/synctest/synctest.go) 的 Test 创建隔离bubble，内部时间使用虚拟时钟，全部goroutine稳定阻塞时才推进。这里只在同步处理器+ResponseRecorder的测试内使用，不把真实网络/外部进程塞入bubble；真实HTTP另行测试。
