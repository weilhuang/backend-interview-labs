# 提示、完整答案与为什么这样做

## H1：只问一个问题

复制后的哪一层还可以改？画出 Order → Lines → Tags 与 Order → Metadata 两条路径。在每个切片/map 处检查：这是新容器，还是只是把访问同一容器的值复制过来？

## H2：最小反例

只有一份订单、一条明细、一个标签就够了。复制后执行 `dst[0].Lines[0].Tags[0] = "活动价"`。如果 `src` 也改变，问题在标签底层数据的共享，不必先研究整个 HTTP 服务。

## H3：只给局部

对非 nil 的标签：分配 `make([]string, len(line.Tags))`，然后用 `copy` 搬元素。把这个步骤嵌在明细循环里。对 map 则分配后逐键赋值。每层先处理 nil，保留 nil/非 nil 空的约定。

## H4：完整参考实现

两份答案都随包提供；只替换 SnapshotOrders 的函数体，不替换包声明、签名或区外代码：

- [逐层显式复制](../answers/explicit.go.txt)：适合第一次读，从订单到明细到标签顺着看
- [函数体内辅助函数](../answers/local-helpers.go.txt)：同一合同，用局部函数拆分职责，整段答案可填入同一个练习区

逐步解释显式版本：

1. nil 输入直接返回 nil：维持 C2，避免不必要分配
2. make 创建顶层结果，长度等于输入：维持订单数量与索引关系
3. `dst[i] = order` 先复制所有字段值：ID 不会漏掉；这一步暂时仍共享容器
4. 非 nil 的 Lines 分配新切片，逐条复制 Line 值：Quantity/SKU 保持，但 Tags 暂时仍共享
5. 每条非 nil Tags 分配新切片并 copy：切断标签的共享路径
6. 非 nil Metadata 分配新 map，逐键复制：切断新增/更新/删除的互相影响
7. 返回 dst：输入始终只读；每次调用、每条输出订单都重新创建自己的容器

设订单数为 N、全部明细数为 L、标签元素数为 T、metadata条目数为 M，工作量与额外容器存储为 O(N+L+T+M)。这是按元素/条目计的结构性描述；字符串字节被引用为不可变值，不声称把每段底层字节都重建了。不能凭这一式预测精确内存或纳秒成本。

## 为什么不用 JSON 转一遍就算复制？

本题接受任意 Go 字符串，含无效 UTF-8 字节；JSON 编解码并不承诺保留所有这类原始字节。序列化还可能改变未导出字段、特定类型或字段语义，且引入不必要的格式契约。这里直接按已知类型复制更清楚。未来确有序列化边界时，另写它的合同和测试。

## 八种错误解对应什么缺陷

所有错误代码在 `wrong-solutions/`，制作验收会把它们逐份放进临时副本，运行同一套公开测试；不会更改学员源码。

- return-alias：直接返回输入，连顶层都没隔离
- shallow-only：只复制顶层，也是本题起点
- missing-map：明细正确却忘记 map
- missing-tags：明细元素复制后忘记里面的 Tags
- empty-to-nil：将非 nil 空输入变成 nil，违背明确合同
- drop-fields：只盯着容器，漏掉普通值字段 ID
- reverse-order：返回值貌似齐全却改变订单顺序
- mutate-source：先偷偷改输入，再复制；不能因为两份都“相等”就通过

“错误解被杀死”必须是业务断言失败，不把编译错误、工具缺失或 panic 算作有效检测。细节在候选证据报告中列出。

## 面试问答：先答机制，再说边界

1. 问：Go 按值传递，为何函数内还能改调用者的切片内容？
   答：传入的是切片值的副本，两个切片仍可能访问相同底层数组。改变元素与重新给局部切片变量赋值不同。追问：append是否影响原切片？先分析容量与是否分配，再看谁持有哪份切片，不能答“总会”或“总不会”。
2. 问：`copy` 是否深复制？
   答：它复制元素值。元素若含切片或map，就仍可能共享其内部数据。追问：[]string为什么本题复制一层就够？string在这里是不可变值，合同不需要可变字节副本。
3. 问：nil slice 与空 slice 一样吗？
   答：它们都可长为0，range都可不迭代，但是否等于nil不同，编码/业务合同也可能区别对待。本题明确保留；别把一题要求泛化为所有接口。
4. 问：深复制就线程安全吗？
   答：不。复制正在并发修改的数据仍需同步；返回后若多人写同一快照也仍需协调。所有权隔离减少共享面，不代替所有并发协议。
5. 问：同一原始map被两条订单引用，复制时要保留共享关系吗？
   答：先问合同。本题要求输出订单独立，所以拆开共享关系；通用对象图复制器可能选择保留别名，合同不同。
6. 问：怎样保证未来加字段不遗漏？
   答：代码评审检查所有可变字段；新增最小反例；用业务调用方回归。不用反射强迫字段布局，也不把一次覆盖率数字当未来保证。
