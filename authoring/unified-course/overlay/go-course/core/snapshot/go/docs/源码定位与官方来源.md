# 公开合同、源码入口与事实边界

## 公共行为先于实现细节

- [Go规范：切片类型](https://go.dev/ref/spec#Slice_types)：切片访问底层数组，长度与容量概念
- [Go规范：map类型](https://go.dev/ref/spec#Map_types)：map的键值关系与nil边界
- [Go规范：追加与复制](https://go.dev/ref/spec#Appending_and_copying_slices)：copy与append的公开行为
- [官方切片介绍](https://go.dev/blog/slices-intro)：辅助理解切片与底层数据的关系；图是概念说明，不作本课程固定ABI承诺
- [内建fuzz教程](https://go.dev/doc/tutorial/fuzz)：种子回归与额外fuzz运行必须区分
- [race detector说明](https://go.dev/doc/articles/race_detector)：动态检测只覆盖实际运行路径，支持平台有边界

本课没有引用上游整段实现，所有业务模型、调用方、测试、错误解和讲解例子均为本课编写。

## 本题工具链与源码版本

本题工具链为官方 Go 1.27.1；go.mod 的1.26.0是语言最低版本。仓库不携带SDK，不自动安装或下载。运行结果须以当前源码对应的独立报告为准，不能用旧日志推断新代码已经通过。

## 从能理解的入口读源码

1. 在对应 GOROOT 打开 `src/builtin/builtin.go`，定位符号 `copy`。这是内建操作的文档与声明入口，不是运行时完整实现
2. 打开 `src/runtime/slice.go`，定位 `makeslice` 与 `growslice`。观察长度/容量检查及分配分支。并非每次源码里的 make 都保证走同一运行时分配路径，编译器可以优化
3. 可选对照 `src/slices/slices.go` 的 `Clone` 与 `src/maps/maps.go` 的 `Clone`：它们提供的是相应容器层的复制，不会替你递归处理本题每一个可变子容器
4. 记录你读到的版本与符号，不背某行号或某个固定扩容倍率。这些实现细节不是本题自动判分的合同

源码文件核对、命令行测试、原生IDE断点是三种不同证据；本题不将命令行验证冒充IDE源码断点验收。

## 为什么不测地址？

要证明业务互不污染，最直接的是修改一侧再看另一侧。空切片实现可能共享无可变元素的内部位置；是否同地址不能代替本题公开合同。禁止使用 unsafe、反射字段布局或运行时私有结构当评分条件。
