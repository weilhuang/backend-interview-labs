# C13 HTTP 工程进阶：两个可运行练习

这是统一 Java Academy 主课程的 Go 增量材料，不是第二套课程根。先完成已有的 greeting、quantity、order-total、snapshot，再按 request-lifecycle → gin-pipeline 顺序学习。本增量不包含 GORM、真实数据库、鉴权、TLS、容器或生产发布，也不宣称整个 Go 课程已经完成。

## 学习闭环

每题都有：可编译 starter → 可见调用方 → 公开合同测试 → 至少一种完整参考实现 → 对应失败的错误实现 → 真实回环 HTTP → 面试追问 → 固定版本源码定位。Go 业务测试由可见 JDK21/JUnit5 桥执行；Academy 的原生导入/Check 和 Go IDE 调试仍需单独验证。

1. 读 task.md 与流程图，用纸先追踪一次 POST 请求
2. 先读 model.go、router.go、cmd/server/main.go，确定谁创建 server、谁接收请求、谁调用 Store、谁写响应
3. 阅读 contract_test.go 的具名子例，再投影 task-info.yaml 的 starter。编译应该成功，业务测试必须失败
4. 只修改标记之间的练习区，按建议顺序让子例逐批变绿
5. 用 Go 测试、真正 httptest TCP 客户端、独立 main 子进程验证三条调用路径
6. 比较答案与错误实现，回答“哪个测试能区分它们”；不要通过修改测试来消除红灯

## 固定环境与离线检查

- Go 1.27.1：沿用主课程官方完整工具链，GOTOOLCHAIN=local 禁止隐式下载新工具链
- Gin v1.12.0：官方模块要求 Go ≥1.25.0。本题固定版本，不用 master/latest
- JDK21、JUnit BOM 5.11.4、JUnit Platform Launcher 1.11.4：与现有纯 Go 桥一致
- Gin 检查固定 -tags=nomsgpack，排除本课不用的 MessagePack 绑定；本课 JSON 绑定、路由与 HTTP 功能不依赖它。所有构建/检查/调用方命令均保持此 flag
- GOPATH、GOMODCACHE、GOCACHE 指向使用者拥有的缓存目录。环境准备阶段允许官方 Go 代理解析已固定模块，接受 go.sum 的校验；检查阶段 GOPROXY=off、GOSUMDB=off、-mod=readonly，不在测题过程中联网补依赖
- go.sum 是内容校验清单，go.mod 的精确 require 与 Go 的最小版本选择共同决定模块图，不能简单把 go.sum 当成“所有版本只出现一次”的锁文件

先自行设置已存在的 GO_EXECUTABLE、GO_MODULE_CACHE、GO_WORKSPACE_CACHE 的绝对路径；下例不会安装工具链：

```sh
export GOTOOLCHAIN=local GOWORK=off GOENV=off GOFLAGS=
export GOMAXPROCS=2 GOMODCACHE="$GO_MODULE_CACHE"
export GOPATH="$GO_WORKSPACE_CACHE/gopath" GOCACHE="$GO_WORKSPACE_CACHE/build"
"$GO_EXECUTABLE" version
# 仅首次准备：在 gin-pipeline/go 目录，保留原 go.mod/go.sum，不运行 go get -u
GOPROXY=https://proxy.golang.org GOSUMDB=sum.golang.org "$GO_EXECUTABLE" mod download
"$GO_EXECUTABLE" mod verify
# 后续练习检查：
export GOPROXY=off GOSUMDB=off GIN_MODE=release
"$GO_EXECUTABLE" test -buildvcs=false -mod=readonly -tags=nomsgpack -p=1 -count=1 -timeout=45s -v ./...
```

缓存缺失是 INVALID_ENV/依赖未准备，不是实现错误，更不能转换成 assumeTrue/skip。准备下载后用当前 go.mod/go.sum 重新核验。task-info.yaml 中保存作者答案及 UTF-16 偏移，placeholder_text 是学员 starter；可见答案不由桥自动覆盖到学员文件。

## 运行完整服务

在任一题的 go 目录：

```sh
GIN_MODE=release "$GO_EXECUTABLE" run -buildvcs=false -mod=readonly -tags=nomsgpack ./cmd/server
```

终端会打印 LISTEN http://127.0.0.1:随机端口。只使用本次打印的 URL；不要猜固定端口，不要停止其他进程。另开终端将它设为 BASE：

```sh
curl "$BASE/healthz"
# net/http 题：
curl -i -H 'Content-Type: application/json' -d '{"sku":"book","quantity":2}' "$BASE/orders"
# Gin 题：
curl -i -H 'Content-Type: application/json' -H 'X-Lab-Key: training-key' -d '{"sku":"book","quantity":2}' "$BASE/v1/orders"
```

成功应返回 201、order-1、book、2；重复请求会产生新的 ID，本课没有幂等键。Ctrl+C 停止自己启动的服务。服务只绑定本机回环，固定大小的内存演示存储不落盘；重启 ID 重新计数。X-Lab-Key 是公开演示字符串，绝不能用于生产安全控制。

## 验证边界

正例、starter、mutant 的真正运行状态以独立 evidence 为准。源码里的预期和命令都不是执行证明。Java bridge 尚未运行时应记 NOT_RUN；native Academy、跨机器网络、TLS、HTTP/2/3、浏览器前端、Docker、GORM、数据库、生产负载一律不由这两题的绿灯推断通过。无需网页前端才能完成 HTTP 合同验证，curl/公开调用方已经提供完整可观察入口。
