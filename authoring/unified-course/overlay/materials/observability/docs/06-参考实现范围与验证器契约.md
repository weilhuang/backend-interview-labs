# 参考实现范围与验证器契约

## 只编辑一个方法，不等于所有参考类都可直接粘贴

每题的UTF16练习区保持一个明确方法。reference-map对应该支架；reference-typed是完整类阅读对照，其中SafeEvents包含额外record，RequestMetrics修改方法归一化，TraceBridge修改getter。它们不作为同一方法区内的替换文本。需在整棵参考源码树单独构建；当前所有Java参考解仍NOT_RUN。

answers/**/*.java只供阅读。Gradle只编译明确的src和test，不能递归把所有可见Java文件都编译进去。

## 本次证据与历史文件必须分开

变体manifest声明完整expected_test_cases及负例expected_failure_cases。未知或空选择直接失败；报告在启动前刷新。每个变体使用随机的新目录和源码/测试快照，先独立执行testClasses并检查当前class文件，再执行测试；旧XML不可参与。本次JUnit集合必须完整、不重复、零跳过；负例失败必须归属声明的class/method及断言类型，完整失败集合必须与声明精确相等，少一个或多一个均拒绝；不能把工具启动失败算杀死错解。

验证器显式拒绝Python -O/PYTHONOPTIMIZE。编写和任务生成工具要求Python3.9+及requirements-authoring.txt中固定的PyYAML版本；依赖需在获准环境准备，本草稿不会自动安装。

## 状态解释

Python普通mock只验证验收脚本如何处理正反证据，不能成为Java或真实后台通过证据。HTTP/链路、指标、Collector恢复、ELK来源、原生IDE应分别记录，局部通过不能提升整套系统状态。
