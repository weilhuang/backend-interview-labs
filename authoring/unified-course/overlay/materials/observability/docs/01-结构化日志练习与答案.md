# C12-01 日志是一条事件，不是任意文本

## 先运行调用方

阅读 `observability-lab/src/main/java/labs/observability/Usage.java`。它给 `SafeEvents.encode` 传入固定 UTC 时间、checkout 服务、路由模板、状态码、trace/span ID 和纳秒耗时；还故意带一个合成 Authorization 秘密。

命令：`bash scripts/verify_java.sh usage`。这是固定输入演示，不是服务实测输出。应看到一行可解析 JSON，duration_ms 为 12，不能看到 `synthetic-secret`。event_id 每次不同，因此不要把整行字符串与固定样例逐字比较。

## 要你补什么

输入：可信枚举/框架路由模板、SDK 生成的关联 ID、单调时钟计算出的耗时，以及不可信请求头。输出：单行 JSON。错误：负耗时或非法状态显式拒绝。编辑 `SafeEvents.encode` 的练习区，保留签名、测试和调用方。

1. 建立固定字段集合；不要遍历请求头。这里的“脱敏”采用**不采集**，不是先全部收集再猜敏感关键字
2. 把时间写成 `Instant.toString()`；状态和耗时保留数字类型
3. 路由只接受框架匹配模板，未知值统一 `UNMATCHED`；不把原始路径或用户输入当字段名
4. 调用 Jackson 序列化。日志行末换行由 EventSink 统一添加

运行 `bash scripts/verify_java.sh test --tests labs.observability.SafeEventsTest`，再主动输入包含 CRLF 的恶意路由。预期：仍只有一行，字段名没有增加。

## H1—H4

- H1：查看 `Routes.safe` 已经提供的白名单
- H2：`LinkedHashMap<String,Object>` 允许数值保留为数字
- H3：`ObjectMapper.writeValueAsString` 负责 JSON 转义；不能用 `"{..."+input`
- H4：参考解 map 版本按固定 key 放入 9 个字段，typed 版本使用一个 record；两者都不读取 headers 的值

## 两种完整答案在哪里

- `variants/reference-map/src/labs/observability/SafeEvents.java`：固定白名单 map，便于看每个字段从哪里来
- `variants/reference-typed/src/labs/observability/SafeEvents.java`：类型化 Event record，字段在类型结构中固定

逐步推理：先收缩允许的数据 → 校验边界 → 规范时间/ID → 交给 JSON 库。不要把 token 截断后留下前后几位当作安全方案。trace ID 也不是密码，不能拿它授权。

## 测试告诉你什么

`jsonHasTypedFieldsAndUtcTime` 验证类型/时间/关联；`dropsAllHeadersIncludingPiiAndMixedCaseNames` 杀死打印请求头；`rejectsDynamicPathAndCrlfDoesNotCreateAnEvent` 杀死拼接/原始路径；`eventIdStableWithinALineAndDistinctAcrossEvents` 为重复采集定义唯一事件；`durationIsNotComputedFromWallClock` 说明墙钟跳到过去不能制造负耗时。

错误解有单独副本，不改业务测试。必须编译成功且出现相应业务断言失败，才算错误解被杀死。

## 错误路径与面试追问

- 机器时钟错了怎么办？跨机 timestamp 用来大致排序，因果关系优先看 trace 父子关系；持续时间用单调时钟。NTP 校时不能消除所有误差
- 日志磁盘写失败怎么办？EventSink 记录可见失败计数并向 stderr 输出固定错误码；不把原始异常/请求体打印出来。该同步文件 sink 是教学边界，高吞吐生产需评估有界异步队列和丢弃策略
- 同一行重采两次？event_id 不变，ES 按 document_id 覆盖；两次真正业务事件必须不同 ID。不要用 trace ID 去重：一次 trace 有多个事件
- 日志能代替审计吗？不能直接等同。审计还有访问权限、完整性、留存与业务责任约束，本课没有实现完整审计系统
