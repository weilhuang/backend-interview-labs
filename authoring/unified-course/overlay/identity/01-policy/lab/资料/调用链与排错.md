# 一次订单请求的完整调用链

先读Usage.java三次调用，再进入安全框架。下面描述源码设计；本轮固定版本的本地Java与真实HTTP验证见根阶段报告，LDAP/SSO尚未执行。

```text
课程提供的中文前端
  -> GET /api/orders/order-a + Authorization: Bearer ...
  -> BearerTokenAuthenticationFilter -> JwtAuthenticationProvider
  -> IdentityTokenDecoder / NimbusJwtDecoder
      固定JWKS -> RSA验签 -> iss/aud/exp/nbf/typ/sub
  -> TrustedSubject.from(已验证Jwt)
      当前tenant对应的roles；忽略X-Tenant/X-Role
  -> OrderController读取仓库中订单的真实tenant
  -> 唯一学员jar中的Policy.authorize
      认证 -> 必需属性 -> 同租户 -> 动作白名单 -> 角色权限
  -> 200；或在修改状态之前拒绝
```

[调用链SVG](identity-call-chain.svg)。隐藏按钮不是授权边界；直接HTTP请求同样需要服务器校验。

## 输入输出合同
- tenant-a reader读取order-a：200；reader审批：403，状态不变
- tenant-a editor审批order-a：200，审批计数增加
- tenant-a admin读取tenant-b的order-b：403
- 无token或错误签名/audience/时间/用途：401
- 不存在的订单：404。本示例403/404会透露存在性差异，实际产品可统一404，但不能省略对象授权
- 内部reason是固定枚举式文本；外部不回显token、密码或内部异常栈

## 当前运行方式
从项目根使用已批准的Gradle8.10.2与JDK21，先按根README检查随包固定依赖锁。运行：
```sh
gradle --no-daemon :identity-01-policy-lab:test
gradle --no-daemon identityCheck
```
测试源码会为JWT与HTTP用例创建本地合成签名/JWKS，不依赖真实员工目录。学员test的finalizedBy任务会运行真实Tomcat HTTP并核对Policy实际类来源；本轮这些Java层已执行通过，新增CI配置尚未运行。

单独运行 `gradle --no-daemon :identity-resource-server:run` 可启动本地页面，但API还需要与配置一致的合成身份服务；本包没有提供已验收的Keycloak/LDAP生命周期环境。不要输入工作账号真实token。

## 定位失败
1. 连接失败先查进程、回环地址与端口，不先改授权
2. 401查受控issuer、目标aud、token有效期与固定JWKS源；不把凭证复制进日志
3. 403查资源真实租户、当前租户角色和动作；认证通过不等于本次操作有权
4. 轮换后短暂401先查发布顺序和刷新预算；不能临时放行
5. TLS证书错误要修CA/SAN，不能跳过验证
6. 目录中断下新登录、session、缓存用户和旧JWT可能不同，后续联邦单元会分别验证

根目录的Python回归只检查源码结构与mock证据判定，不执行RSA服务、Tomcat或浏览器；它与Java/容器/原生Academy验证分别记账。
