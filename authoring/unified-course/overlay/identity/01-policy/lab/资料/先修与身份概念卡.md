# 从零读懂企业身份

这是 C15 的先修补课，不要求先会 LDAP、OAuth、OIDC、Keycloak。先读卡片，再用“订单属于哪个公司”的例子回答诊断题。涉及 token 的样例只用合成身份，截图与日志不得包含 token、密码或 cookie。

## 先修诊断（先回答，再看末尾解释）
1. 浏览器显示“你好，小李”能证明服务器允许小李修改订单吗？
2. `127.0.0.1:18081` 中 IP 与端口分别帮我们找到什么？容器内的 localhost 指向谁？
3. 把 JSON 做 Base64 编码后，别人还能读取、修改它吗？
4. 两家公司都叫“管理员”的员工，应该能互相查看订单吗？
5. 删除浏览器 cookie，是否立即让所有设备已经拿到的 JWT 失效？

解释：①不能，服务器每次操作仍要授权；②IP 找主机网络接口，端口找监听进程，容器内 localhost 指容器自身；③编码可逆，不证明真实性或保密性，签名/加密另有职责；④不能，角色还必须受租户边界限制；⑤不能，目录账号、登录会话与已签发 token 是三种状态。

## 第一组：一次请求里谁负责什么
- 身份 Identity：用于稳定指向一个人的标识。显示名会重名/改名，不能当永久主键。应用一般以“发行方 issuer + 主体 sub”定位外部身份
- 认证 Authentication（authn）：回答“来的人是谁、证明是否可信”。密码验证、WebAuthn、已验证的 token 都可能参加这个过程
- 授权 Authorization（authz）：回答“这个身份可否对这个具体资源做这个动作”。登录成功不是所有权限成功
- 主体 Subject：发起动作的人或服务；资源 Resource：订单；动作 Action：读取、审批；决策 Decision：允许/拒绝及内部原因
- 租户 Tenant：应用把不同组织的数据与权限隔开的业务边界。本课 tenant-a 与 tenant-b 是两家合成公司，不是两个名字不同的页面
- 角色 Role：一组权限的名字。reader 可读，editor 可读和审批，admin 在本课也只能执行明列动作，不能跨租户
- RBAC：按角色查权限表；ABAC：再看主体/资源/环境属性，例如部门、值班时段、订单金额。ABAC 不是执行用户提交的任意表达式
- 默认拒绝：没有明确允许规则时就拒绝。未知动作、空租户、缺失身份不能解释成“兼容旧客户端所以通过”

## 第二组：会话与 token
- Cookie：浏览器按照域、路径与 SameSite 等规则自动附带的一小段数据；可以保存会话编号，但 cookie 本身不等于登录
- Session 会话：服务端维护的一段登录状态，cookie 常只携带一个随机引用。退出时可删除服务端 session
- Token 令牌：表达授权或身份结果的凭证。持有 bearer token 的人通常就能使用其能力，不能贴在群聊、截图、URL、错误日志里
- Access token：发给资源 API 使用；API 必须验证它属于自己（aud）且满足权限。它未必是 JWT，也可能是不透明字符串
- ID token：OIDC 发给登录客户端的身份结果。不是订单 API 的通行证，不能拿它代替 access token
- Refresh token：用来换新 access token 的长期能力，泄漏代价更大。本首片不实现刷新与存储
- JWT：一种紧凑声明格式，常见形式是头.payload.签名。头和正文只是编码，不是加密；必须完成算法、验签、issuer、audience、时间和用途检查后才信任
- iss：谁签发；sub：其主体；aud：发给谁；exp：过期时间；nbf：最早可用时间；kid：选择已信任公钥集中的哪把钥匙
- JWKS：一组 JSON 公钥。资源服务应从受控配置取 JWKS 地址；不能跟着 token 自带的 jku/x5u 去任意站点取钥匙
- 密钥轮换：新旧公钥短时并存，旧 token 按有效期继续验签；发布新公钥、启用新私钥、等待旧 token 到期、移除旧公钥是不同步骤。删除目录用户也不会神奇地抹掉离线验证中的签名

## 第三组：浏览器登录协议
- OAuth 2.0：授权框架，规定客户端怎样获得对资源的受限访问。它单独不定义统一的“用户登录资料”协议
- OIDC：在 OAuth 上补身份层，定义 ID token、发现文档和用户信息等。Keycloak 是可以实现这些协议的产品，协议不是该产品专用格式
- Authorization Server / IdP：签发凭证的服务；Client：请求凭证的应用；Resource Server：保护订单的 API；Resource Owner：授权访问的人
- 授权码 Code：浏览器回调携带的短期一次性码，随后兑换 token；应使用授权码流，而不是在新项目中默认使用隐式流或密码模式
- state：把发起登录与返回的浏览器请求绑定，防止跨请求混淆；必须不可预测、绑定会话、一次消费，拒绝缺失/错误/重放
- nonce：登录请求生成的随机值，OIDC ID token 中的值必须与本次请求匹配；不是所有 access token 都有 nonce
- PKCE：先发 verifier 的 S256 摘要（challenge），兑换时提供原 verifier，使偷到 code 的人不能直接兑换。不能用固定 verifier，也不能把 challenge 当 secret
- redirect URI：认证服务允许浏览器回来的精确地址。`http://127.0.0.1:18081/callback` 与任意路径/域名不同，不应用 `*` 放宽
- BFF：由后端处理 code/token，浏览器只用安全 cookie 的一种架构；要考虑 CSRF、HttpOnly、Secure、SameSite 与登出。与只接受显式 Authorization header 的无状态 API 配置不同

```text
浏览器 -> 应用 /login -> IdP /authorize (state, nonce, PKCE challenge)
浏览器 <- IdP 登录页面；用户在 IdP 认证
浏览器 -> 应用 /callback?code=...&state=...
应用   -> IdP /token (code, verifier, 精确 redirect_uri)
应用   <- access token + ID token（不同用途）
浏览器/应用 -> 订单 API -> 验证 access token -> 对具体订单授权
```
本课源码重点展示最后一行，前面登录回调流程尚未实现，不能把预置 token 实验称为真实浏览器 SSO。

## 第四组：LDAP 目录
- Directory 目录：面向查找的层次数据结构，常存组织、用户、组；LDAP 是访问它的协议，不是某一数据库产品的名字
- DN（Distinguished Name）：一条目录记录在树里的完整名字，例如 `uid=alice,ou=people,dc=academy,dc=invalid`
- RDN：DN 最左边的一段，例如 uid=alice；OU 是组织单元；dc 是域分量。移动 OU 会改变 DN，因此 DN 不一定适合当永久身份主键
- uid：常见登录名属性，不是 DN；cn 是常用名，displayName 是显示名。稳定 ID 依产品可能是 entryUUID 或 nsUniqueId，应明确映射
- Search base：从哪一节点开始；scope=base 只查节点，one 只查直接子节点，sub 查整个子树。搜索范围不是越大越好
- Filter：筛选表达式，例如 `(uid=alice)`；用户输入是值，`* ( ) \ NUL` 必须按 RFC4515 转义。DN 的 RFC4514 转义规则不能替代 filter 转义
- Bind：建立连接的认证状态。服务账号 bind 用于只读搜索，用户 bind 用于验证用户凭证；非空 DN + 空密码可能有“未认证 bind”语义，应用必须预先拒绝空密码
- TLS：验证服务器证书与主机名、加密传输。LDAPS 从连接开始使用 TLS；StartTLS 先升级连接再 bind。不能忽略证书错误、不能验证失败后自动降级为明文
- size/time limit：限制最大结果量与查找时间；网络连接/读取也要有超时。多个匹配不应“随便取第一个”当成认证成功
- Group 组：常以 member 存成员 DN。目录组到应用角色是显式映射，不应把所有 LDAP 组名直接赋成管理权限

```text
dc=academy,dc=invalid
├─ ou=people
│  ├─ uid=alice  (稳定ID=A，tenant-a)
│  └─ uid=bob    (稳定ID=B，tenant-b)
├─ ou=groups
│  └─ cn=order-readers (member=alice DN)
└─ ou=services
   └─ uid=fixture-reader (只读搜索，不可改目录)
```

## 第五组：Keycloak 与联邦
- Realm：Keycloak 的一套用户、客户端、配置边界；一个 realm 不自动等于业务租户
- Client：一个接入应用的登记；public client 无法保密 secret，不能把 admin client 或长期密钥放前端
- Realm role / Client role：全 realm 或某 client 的角色命名空间；业务租户角色还需额外约束，不能见到 admin 字符串就放行
- Federation 联邦：Keycloak 到 LDAP 等用户来源的连接/映射；与“通过另一个 OIDC 身份提供方登录”的 identity brokering 要区分
- 真源 Source of truth：员工启停、组织组归属由谁最终决定；本课程 LDAP 为目录真源，应用订单归属由应用仓库决定
- Import/cache/sync：复制用户、缓存属性、同步变更是不同操作。LDAP 不可用时，已缓存身份、已有 session、旧 JWT 可能表现不同
- 撤权窗口：从目录取消权限到所有相关请求拒绝的最长预期时间，受同步、会话、token TTL、在线检查影响。必须测量并记录，不用“实时”二字替代证据

高危操作在线目录检查、真实联邦登录、同步、缓存与撤权窗口属于后续主题。本候选没有实现这些联邦策略或真实目录测试。
