# 一个课程，一套按需环境

先完成当前题目，再检查当前题目；不要为了“装好环境”一次启动全部中间件。所有命令均在**统一课程根目录**执行，脚本也支持路径含中文和空格。

本入口不安装软件、不改系统权限、不启用架构仿真、不结束未知进程、不删除卷，也没有 reset/prune 命令。`stop` 只停止自己的容器。历史资料中的旧 `scripts/course.sh`、`up/down` 或原课程目录命令不是统一包入口，请使用本页命令。

## 1. 先选当前题目

```bash
# 仅用 Python 检查发布文件与配置；不运行 Java、Docker 或 GUI
bash scripts/lab.sh verify

# 基础 Java 题：检查完整 JDK，无须 Docker
bash scripts/lab.sh doctor java

# 列出统一课程每题路径、profile 与真实 Gradle 项目名
bash scripts/lab.sh profiles

# 查看计划，不执行测试，不能把 dry-run 当作通过
bash scripts/lab.sh check mysql/04-isolation/04-mvcc --dry-run
```

题目路径以 `profiles` 实际输出或[逐题映射](题目环境映射.md)为准。不要凭原先独立课程的 Gradle 项目名猜测。统一根只有一个 `course-info.yaml`、一个固定Gradle发行配置和一份课程序列；内部材料目录用于保留依赖与资料。官方Academy发行/导入会剔除gradlew、gradlew.bat和gradle-wrapper.jar，因此发行包的构建统一使用下文固定发行启动器，不要求重新补回Wrapper。

### 官方发行没有Wrapper时的固定Gradle启动器

```bash
# 离线优先：已有的官方固定ZIP，必须匹配保留properties中的SHA256
bash scripts/gradle.sh prepare --zip /你的实际路径/gradle-8.10.2-bin.zip

# 只有明确执行这个选项才联网下载官方固定发行
bash scripts/gradle.sh prepare --download

# 检验缓存完整性，不运行Java或联网
bash scripts/gradle.sh verify

# 原Gradle参数原样传递；环境入口check与capstone installDist也调用它
bash scripts/gradle.sh --no-daemon --max-workers=1 :c00-01-workspace-lab:test
```

仅支持properties指定的官方Gradle8.10.2发行URL及固定SHA256，不搜索PATH里的浮动Gradle，不重新封装或恢复Wrapper JAR。普通构建若缺运行时直接失败，并给出prepare提示；不会悄悄下载。`prepare --zip`与`prepare --download`本身只用Python标准库，不启动Java。外层使用bash和python3，官方导入没有保留脚本exec位也能运行；受测执行平台边界是Linux，macOS仍需实测，不声称Windows启动或bat受测。

默认发行缓存位于课程树外：Linux的XDG_CACHE_HOME/totalacademy/gradle（未设则~/.cache/totalacademy/gradle），macOS的~/Library/Caches/totalacademy/gradle。可显式设置绝对LAB_GRADLE_CACHE，指向课程树外的新目录；不能指向课程build或其他课内目录。同一固定发行复用一次缓存，保留原ZIP加解压文件以便每次执行前校验，不能把这部分磁盘占用隐去。

准备先验证整份ZIP的SHA256，再检查所有条目：拒绝绝对路径、..穿越、反斜线/盘符路径、符号链接、特殊文件、重复路径及超限展开。使用独占新payload目录，全部文件完成后以不覆盖已有对象的硬链接原子发布完整性凭证。每次执行前重验来源ZIP与所有解压文件，不仅相信一个可修改的版本号或凭证。损坏、陌生现有缓存或已有准备锁均失败；不会自动覆盖/清空旧目录，只清理本次未发布的临时目录。

确需使用你已经独立信任的现有Gradle时，可设置LAB_GRADLE_BIN为绝对可执行文件路径。入口会运行该文件的--version并严格要求8.10.2，然后传递原参数；**版本检查≠来源认证**，该显式覆盖绕过托管ZIP来源验证，不应指向未知下载文件。入口不自动采用系统PATH里的gradle。发行ZIP、URL和校验值变更须经过新的审核，不要用关闭校验解决下载失败。

## 3. 完整判题：通常不用先 start

```bash
# 准备真实 Docker 的检查只针对当前需要的 profile
bash scripts/lab.sh doctor mysql

# 如果曾手动启动演示服务，先停止，保留数据
bash scripts/lab.sh stop all

# 完整检查当前题目；示例路径从映射取得
bash scripts/lab.sh check distributed-course/services/06-transactions
bash scripts/lab.sh check kafka/03-inbox/practice
bash scripts/lab.sh check redis-course/redis/04-consistency
```

`check <题目路径>` 使用映射中的原生扁平 Gradle 项目，执行完整 test；不会以快速 unitTest 替代：

- MySQL/Redis：test 本来就包含真实服务测试，不跳过 integration 标签
- Messaging：强制 `-PwithDocker`，真实 broker 测试不能静默跳过
- Distributed 06/07：test 已包含真实集成类；只执行一次，保留 Academy 完整 Check 行为。05/08 则追加现有 integrationTest
- Framework 03：追加现有 MySQL integrationTest
- Capstone：test 后追加真实 MySQL/Redis/Kafka/gRPC integrationTest
- 其他有 integration-test 源码的题目：追加对应 integrationTest；没有集成源码的纯 Java 题仍执行真实单元合同检查

缺 Docker、断言失败或构建失败均返回非零。`--dry-run` 只显示命令；`verify` 只验证结构；`health` 只验证运行健康。三者都不能代替完整 check、Academy 原生按钮或 UI 验收。

真实测试由 Testcontainers 创建隔离容器、随机端口与本次测试数据，测试后按课程关闭；不会改用 Compose 的持久数据。**无需先启动手动 profile**，这样避免同时出现两套数据库/MQ。若本课程还有常驻容器，入口要求先 `stop all`；它不会擅自停止其他项目或测试进程。

部分拓扑比一个手动 profile 重：Redis 05 有主从；Distributed 06 有两个 MySQL；Kafka 06 有三 broker 副本实验及 MySQL。不能把单节点 health 当作这些实验完成。低内存时逐题运行，勿直接运行整课的重型全量 gates；准确需求见[逐题映射](题目环境映射.md)。

## 4. 需要手工连接时才 start

```bash
# 仅启动指定组件；只拉取缺失的同一固定镜像
bash scripts/lab.sh start mysql
bash scripts/lab.sh health mysql
bash scripts/lab.sh status
bash scripts/lab.sh resources

# 结束当前实验，保留容器和卷
bash scripts/lab.sh stop mysql
bash scripts/lab.sh start redis

# 可选：明确确认停止本课程旧 profile 不再需要的服务
bash scripts/lab.sh start kafka --stop-others
```

默认不启动任何中间件；裸 `start` 仅检查纯 Java profile。所有 profile 都是显式的：java、mysql、redis、redis-mysql、kafka、kafka-mysql、rocketmq、rocketmq-mysql、kafka-rocketmq、distributed-outbox、capstone。

新 profile 与仍在运行的旧 profile 不一致时，入口先说明冲突并退出。你可先 `stop`，或明确加 `--stop-others`；它仅停止同一课程项目下不再需要的服务，共用服务保留，数据卷保留。不会停止其他目录/其他人项目的容器，也不会为端口冲突结束任何未知进程。

`start` 使用 Compose `--wait`，不是后台发出命令便宣称成功。失败返回非零并保留数据，可能已经有部分组件启动，应查看 `status`/`logs` 后手动停止。`health` 要求选定容器运行且 healthy；RocketMQ 还检查实时管理 RPC、实际端口绑定、宿主 Proxy HTTP/2 SETTINGS/PING 往返。

## 5. Capstone：前端已在后端里

```bash
# 默认最终阶段；开始前要完成该阶段的后端学习区
bash scripts/lab.sh doctor capstone
bash scripts/lab.sh start capstone --stage 05-defense

# 打开 http://127.0.0.1:8088
# 检查真实订单幂等/冲突/取消和 Kafka/gRPC 投影
bash scripts/lab.sh workbench-check capstone

# 完整阶段测试（临时容器）与演示服务不并行
bash scripts/lab.sh stop capstone
bash scripts/lab.sh check capstone/stages/05-defense
```

切换阶段也使用同一个入口，例如 `start capstone --stage 02-reliability`。阶段从实际课程映射验证，不接受任意路径。入口用该题的真实 Gradle 项目运行 installDist，并检查实际输出 lib 目录，再把其挂入应用容器，避免空挂载或原独立课程路径失效。

预置页面来源是 `materials/backend-capstone/app/src/main/resources/static/index.html`，随 Gradle 资源一起分发，后端同源提供页面和 API；无需 Node、CDN、代理或手接 CORS。详见保留的[前端说明](../materials/backend-capstone/docs/前端使用.md)。其中旧独立目录启动命令请以本页为准，历史截图与CI记录也不能冒充统一包的新验收。

`workbench-check` 在任何业务HTTP之前，必须核对当前项目唯一 orders 容器仍健康，且其实际发布绑定恰为当前配置的 127.0.0.1:CAPSTONE_HTTP_PORT。改了.env却未重建绑定、缺失/多重绑定或非回环发布时直接拒绝，不会向另一个端口上的课程发送请求。

`workbench-check` 明确会创建一个唯一请求号教学订单，验证重复请求/409冲突，然后取消自己的订单并触发已有业务 replay；它不是只读检查，也不清空数据。返回成功是这一次真实 API 链验证，不等于浏览器交互或所有断网/恢复场景通过。需要真实浏览器验收仍使用保留的作者 browser-smoke 并单独报告。

Capstone 的 MySQL/Redis/Kafka 使用独立项目网络/数据卷，数据库端口不对宿主发布；仅 orders 的 HTTP 回环端口发布。这样不用改变原实验的数据库名、认证契约和网络DNS，也不会把手动练习表混入最终项目。

### 故障题使用同一入口

```bash
# 停止依赖，保留容器与数据卷；然后按题面观察业务行为
bash scripts/lab.sh pause-service capstone --service mysql
bash scripts/lab.sh recover-service capstone --service mysql

# 暂停/恢复delivery，用于积压与重放题
bash scripts/lab.sh pause-service capstone --service delivery
bash scripts/lab.sh recover-service capstone --service delivery

# 只有题目明确要求进程崩溃时，才使用强制SIGKILL
bash scripts/lab.sh crash-service capstone --service orders
bash scripts/lab.sh recover-service capstone --service orders
```

pause-service/recover-service 只允许本课程 capstone 的 mysql、redis、kafka、delivery、orders；crash-service 只允许 orders/delivery，不能强杀数据库或MQ。必须明确写 capstone 与 --service，不接受任意容器名、其他项目或未知服务。没有已存在且唯一的本课程容器时直接拒绝，故障命令不会暗中新建整套环境。

恢复使用**同一个容器**，保留原检查点挂载和数据卷，不会因为命令未重复 --stage 而把02阶段重建成默认05阶段。恢复后有界等待协议级healthy；OOM、退出或超时均失败。恢复容器不等于业务恢复题已完成，仍须按照题面重放事件、核对订单/投影并运行完整检查。

## 6. 项目、端口、版本与数据隔离

第一次 `start` 排他创建 `infra/.env`，仅当前用户可读写，不覆盖已有配置。里面只放教学样例密码，不能填生产密码/真实用户数据；应被根 `.gitignore` 排除。环境变量中的 COMPOSE_PROFILES 或同名 IMAGE 键不会偷偷覆盖所选服务/台账。

| 用途 | 默认宿主地址 | 网络内地址 | 检查方式 |
| --- | --- | --- | --- |
| MySQL手动实验 | 127.0.0.1:13306 | mysql:3306 | 普通实验用户对目标库 SELECT 1 |
| Redis手动实验 | 127.0.0.1:16379 | redis:6379 | 带教学密码 PING |
| Kafka手动实验 | 127.0.0.1:19092 | kafka:9092 | broker API 查询；正确区分两套 advertised listener |
| RocketMQ手动实验 | 127.0.0.1:18081 | rocketmq:8081 | NameServer/Broker 管理RPC + Proxy HTTP/2往返；不发布9876/10911 |
| Capstone工作台 | 127.0.0.1:8088 | orders:8080 | 依赖健康、API业务检查和浏览器另验 |

`LAB_PROJECT_NAME=auto` 根据**当前课程绝对路径**生成 totalacademy-短哈希；capstone 附加 -capstone。不同解压目录默认不会互认容器/卷，但固定宿主端口仍可能冲突，需修改各自 `.env`。如果你移动课程目录，项目名也会改变；旧卷不会消失，却不会自动接管。移动前先记录 `doctor`/`status` 的精确项目名；必要时在新目录明确填相同 LAB_PROJECT_NAME 并核对归属。

自定义项目名仅允许 totalacademy-小写字母数字连字符后缀；端口限制1024–65535、规范ASCII十进制且互不重复；前导0（例如08088）、符号等非规范写法直接拒绝，不能绕过数值去重。密码允许12–128位字母数字及 `_!@%+=.,:-`。KEY=VALUE 不执行 shell，不接受变量展开、空格、引号或命令。

修改 MySQL 样例密码不会自动修改已有卷的账户，修改镜像版本也不自动迁移数据。先核对原配置与备份，不要靠删除卷掩盖失败。环境变量/容器元数据仍可被有 Docker 权限的人查看，这不是生产密钥管理。

统一入口只支持明确本地 Docker 端点。在任何 daemon info、Compose操作、真实Testcontainers判题或故障操作前，先独立校验 DOCKER_HOST，再只读解析显式 DOCKER_CONTEXT（未设置则读取当前context）的 Docker endpoint。两者都必须明确本地；即使本地context覆盖了Docker CLI的远端DOCKER_HOST，也会拒绝，因为Java/Testcontainers仍可能读取DOCKER_HOST。

允许：绝对unix socket（例如 unix:///var/run/docker.sock、Docker Desktop用户目录socket、rootless的/run/user/UID/docker.sock）、本机 npipe:////./pipe/名称、tcp://127.0.0.1:端口或tcp://[::1]:端口。拒绝：SSH、远端TCP、远端命名管道、相对路径、含糊或缺失endpoint，以及需要DNS解释的localhost名称。读取context只是客户端只读元数据，不接触daemon；校验失败不运行Compose、HTTP业务或测试。入口不切换context、不改DOCKER_HOST、不使用sudo、不修改用户设置。

范围：本地daemon门禁仅覆盖scripts/lab.sh及其check等子命令。直接运行Gradle（包括scripts/gradle.sh）或Academy原生Check仍按原Testcontainers配置解析，不继承CLI的隔离保证。首次运行容器题、或切换Docker配置后，先执行对应profile的doctor；CI须记录它自己的本地daemon配置。不能据此宣称所有原生入口都已禁止远端执行。

远程 context 的localhost是daemon所在机器，不能用其容器绑定证明本机HTTP服务归属。需要远程环境时，应在该环境里使用本地daemon运行完整入口，不能绕过此门禁、开放公网端口、改socket权限或自动建隧道。

## 7. 内存、磁盘与只读占用

Compose 服务逐个设内存/CPU与日志上限，准确合计由配置生成在[清单](环境配置清单.md)。例如单 Redis 的上限最小；capstone 五服务合计已经约3.2GiB，仍需 Docker VM、文件缓存与宿主 JDK/IDEA 空间。该数不是实测峰值，也不能承诺某台低配 Mac 一定运行顺畅。

实用原则：

1. 纯 Java 题不打开 Docker；临时结束学习可 `stop all`
2. 每次只查一题，不把 capstone、Kafka三broker、RocketMQ和IDEA构建并行运行
3. 手动环境与 Testcontainers 不同时运行；进入完整测试前保留卷停止手动环境
4. 同一 daemon 相同镜像引用复用已有镜像层；镜像、Gradle依赖缓存、测试数据、Compose卷、build输出仍是不同占用。换机器或daemon不共享缓存
5. `resources`（别名 `resourceusage`）仅对这两个课程项目运行 docker stats，并展示全局只读 docker system df。主机剩余磁盘不等于 Docker VM 可用空间；测试临时容器不在这两个项目stats中
6. stdout日志每容器3×10MiB；Kafka保留24小时并有段大小约束；RocketMQ内部各类别日志另设小文件与归档。它们都不是整个卷的总硬磁盘配额，不能承诺长时间大量写入不会增长
7. `stop java` 是明确的无操作，不向 Compose 发送省略服务名的停止命令，也不停止其他 profile。停止不回收镜像/卷的磁盘空间。入口不做任何自动清理；如需删除，先另行识别对象、备份并明确确认，不运行全局 prune

本次没有真实 Docker，未测量首次镜像下载字节、冷启动时间或内存/磁盘峰值，因此不把规划预算写成实测结果。

## 8. Mac与Apple Silicon边界

统一脚本设计兼容 Python3.9+与macOS Bash3.2，路径由自身定位；Compose没有强制platform。docker doctor显示实际 daemon 架构与显式 DOCKER_DEFAULT_PLATFORM，并保留用户设置，不能从宿主芯片猜远端架构。

**本统一包未完成 Intel Mac 或 Apple Silicon 实机验证，也未借用用户Mac执行本轮工作。** 历史镜像元数据审核曾记录原固定台账的 amd64/arm64 manifest；它不能替代统一根构建、绑定挂载、权限、原生Academy、Testcontainers或前端业务实测。遇到 no matching manifest 先核对具体引用和daemon；不要自动改镜像版本或强制amd64仿真。

Docker Desktop 的操作系统与安装许可按[官方macOS安装要求](https://docs.docker.com/desktop/setup/install/mac-install/)处理。Engine28.0安全基线来自[官方回环端口发布说明](https://docs.docker.com/engine/network/port-publishing/)；本入口不更改网络、安全设置或安装状态。
