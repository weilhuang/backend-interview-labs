# 扩展学习与验收范围

## 内容顺序

- C11：镜像和优雅停止 → Compose 就绪与幂等 seed → 容器网络 → Kubernetes 控制器/探针 → 配置 → 发布。前三课共用订单 API 与 Redis 示例，后三课使用明确拥有的 kind 实验环境
- 可观测性：安全结构化日志 → 低基数指标 → 跨服务上下文。先验证本地 Java/HTTP 合同，再学习 Collector、Prometheus、Jaeger 等外部后端
- Go：greeting → quantity → order-total → snapshot → request-lifecycle → gin-pipeline。Java JUnit 桥调用真实 Go 编译与公开合同，不用静态字符串搜索代替业务验证
- C15：租户与角色策略 → 真实资源服务器 HTTP/JWKS 合同。实际 LDAP、Keycloak 联邦、浏览器 SSO 尚未接入

## 工具与环境

所有 Java 构建固定 JDK21、Gradle8.10.2，Java 最终模块使用 STRICT 依赖锁。C11/Kubernetes 的桥还需要 Python3 和 PyYAML6.0.2；它们的本地策略/YAML 检查不启动 Docker。Go 固定1.27.1；HTTP/Gin 的模块缓存必须预先准备，检查按只读离线方式使用，Gin固定1.12.0并使用nomsgpack标签。具体参数见每题的统一课程入口。

一个 `shared/versions.env` 是生成课程的镜像台账。镜像标签固定不等于镜像 digest、安全或跨架构验证。现有 OTEL_COLLECTOR_IMAGE、JAEGER_IMAGE、PROMETHEUS_IMAGE 仍缺已审值，因此相关后端保持 NOT_RUN，不用 guessed tag 绕过门禁。

## 什么不能由局部绿灯推断

- 本地 C11/Kubernetes 桥通过不证明 Docker 镜像、真实 Redis/Lua、Kubernetes 控制器或 rollout 通过
- 本地 C12 HTTP 通过不证明 Collector、ELK、SkyWalking、Prometheus 或 Jaeger 接入通过
- 合成签名/JWKS 与本地资源服务器通过不证明真实身份源、LDAP、联邦或浏览器登录通过
- Go业务合同通过不证明原生IDE调试、生产TLS/HTTP2/HTTP3、生产鉴权或负载能力
- retained 旧测试与模型保真检查不等于当前完整源码又执行了一轮测试

`fullCheck` 保留扩展基础设施的 fail-closed 门禁。只有源码CI、单一官方ZIP导出与干净导入、完整当前题目原生检查、reset与同归档真实环境验收各自提供本次绑定证据后，才可作为官方发行物提供。
