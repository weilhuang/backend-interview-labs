# 统一课程可靠性修复阶段报告

## 本轮处理的问题

源码验收运行 [36921316341](https://github.com/weilhuang/backend-interview-labs/actions/runs/36921316341) 的中文字体准备已通过，但两项后续检查失败：

1. 框架界面验证在后台服务启动后立即检查进程身份，尚未进入 HTTP 等待就退出。本地用同一子进程的延迟 exec 重现了这个时间窗口。
2. Redis 学员源码夹具在停止主节点后，连接仍存活的副本时发生 Jedis 握手读超时，尚未执行学生的提升逻辑。这是基础设施失败，不能记为“学生答案被正确拒绝”；现有门禁保留失败。

Redis 超时的底层原因仍未确定。现有证据不能证明是 DNS、容器重连或 Redis 事件循环问题。

## 修复和补强

- 启动脚本仅等待本次直接子进程完成启动身份转换，持续核对父 PID、启动时间和本次实例标记；提前退出、其他身份或有界等待超时仍然失败。停止操作的归属限制保持不变。
- 02、07 演示应用通过响应头返回本次本地实例标记。HTTP 检查要求恰好一个匹配标记，并在响应后再次确认进程仍存活且归属正确。请求不携带标记；无标记、错误标记和重复标记的外部 HTTP 200 均不能通过。
- 响应标记仅用于关联本地 loopback 演示实例，不是生产鉴权凭据。业务 API、参考答案和练习区没有改动。
- Redis 只对副本的连接握手和 PING 提供有界准备重试，成功后返回同一连接。学生的提升操作只执行一次；随后独立断言副本已成为 master，防止仅关闭只读限制的错误解误过。
- Redis 准备的 15 秒是停止发起新重试的预算，不是强制抢占；在途操作仍使用原有 500 毫秒连接/读取超时。超时、取消和清理异常均保持明确失败。
- 统一根 test、unitTest 保留 84 个课题，并明确加入 4 个支撑模块的测试任务。JMH 基准不纳入这两个入口；缺失必需测试任务会失败。新增 Redis 支撑夹具的 12 项测试不会因只聚合课题而遗漏。
- 教案中的集成测试说明依据实际 Java 文件生成，空目录不再改变生成结果；Redis 的共享集成源码仍然保留。

## 已取得的证据与限制

- 本地真实子进程及 HTTP 夹具覆盖正常延迟启动、退出、错误身份、独立 HTTP 等待和响应标记。无标记、错误标记及重复空响应头等反例均失败。
- 02、07 新源码使用既有依赖重新编译，JUnit 分别通过 7 项、5 项；实际本地 HTTP 与 start/check/stop 通过。07 此次仅使用 H2，没有运行真实 MySQL。
- 首次离线 Gradle 解析现有 Jackson 锁图失败，随后一次自建 JUnit 启动器因未正常退出而超时；这些记录保留，不计为通过。上述直接编译和 HTTP 结果不等于完整 Gradle 构建、浏览器流程或官方导入通过。
- Redis 无 Docker 的夹具测试通过 12 项，原失败 XML 仍被门禁拒绝。真实 Redis 故障切换及“仅关闭只读”错误解的动态验证仍需新 Actions 结果。
- 真实离线 Gradle 模型显示根 test、unitTest 各有 88 个直接依赖；原 84 课题模型校验通过。单独执行 redis-engineering-support:test 的 XML 确认 12 项通过、无失败或跳过。原 90 份依赖锁未改，没有运行全部根测试。
- 合并后仍为 9 个课程输入、1 门统一课程、11 个章节、84 个任务、136 个练习区；练习区位置、长度和原答案字节保持不变。新增支撑测试后生成资产为 1213 份、保护文件为 581 份。
