## 每课首页必须出现的版本前置信息

课程开头使用中文表格，并附一条开课自检操作。内部试点包目前不需要前端/Docker时明确写“不需要”，不是留空；以后需要时替换为真实精确版本。

| 项目 | 必填信息 |
|---|---|
| 本课版本与级别 | 课程版本、入门/进阶/高级范围、先修与完成标准 |
| JDK 与构建 | 发行商和完整版本、目标版本、Gradle/测试 JVM、JUnit；没有 Java 时注明 |
| IDE 与 Academy | 验证的产品/build、插件版本；Go 等额外插件与许可要求 |
| 预置前端 | 是否需要；发布版本、Node/包管理器、锁文件、构建产物、端口/API 配置 |
| Docker 与镜像 | 是否需要；engine/Compose 验证版本，共享环境版本，镜像键/版本/摘要 |
| Testcontainers | 是否需要；库版本、如何读取相同镜像台账和启动方式 |
| 资源与服务 | 必须运行哪些服务、实测资源、端口、启动/检查/停止、远程连接方法 |
| 教学素材 | 项目入口、所有测试、每节标准解、源码阅读入口和数据重置范围 |

课程包不得依赖作者本机的缓存或未提供的前端。首次下载依赖失败要与编码错误区分。尚未冻结的表可以用于审阅，但不能作为“可运行发行版”交付。

## 一节课必须交付的完整闭环

1. 企业场景：谁在调用、输入规模、正确性目标、最常见失败是什么
2. 概念与图解：必要术语、中文解释、ASCII 关系/时序，至少一个具体输入输出
3. 运行现成工程：指出调用入口、配置和全部测试，先看到正常与失败样例
4. 自己编码：给任务边界和修改点，每一阶段运行可见测试验证
5. 深入原理：实际核心源码的条件/状态/分支；不适合源码题时给机制和明确边界
6. 企业约束：增加重复、并发、超时、失败恢复、容量、权限等真实条件
7. 标准解：直接可读的完整实现与逐步解释，测试意图、复杂度、替代设计和局限
8. 面试与迁移：基础机制题、代码/场景题、深入追问，至少一个换条件后独立完成的练习

题目数量随主题需要安排，不用一堆相似问句填数。若合并几个任务构成一节课，要在每个步骤指出如何使用/验证，不能等最后才给一个巨大测试。

## 前端与完整调用链的验收

- 有业务界面的课：制作方先完成前端，学习者按中文步骤启动/打开、点哪项、输入什么、应看到什么
- 界面必须连接真实实验 API，演示数据或模拟模式明确标注，不能把静态占位页称为联调完成
- 至少验证正常、加载、空结果、输入非法、接口错误/超时；实际状态码与界面一致
- 提供非图形调用入口（CLI/HTTP 请求或测试），便于排除前端问题并单独练后端
- 后端课不要求学习者修前端才能通过本节；对接失败先检查环境和契约
- 前端/后端/环境版本一起记录；C00/C01 等纯 Java 课可明确“不需要前端”

## 共享环境与测试同源

唯一真源为 `infra/versions.env`，Compose 使用 `infra/compose.yaml`，统一操作入口为 `scripts/lab.sh`。支持动作按实际脚本公开：doctor、up、check、down、reset、build、config、verify；不能在教案虚构一个不存在的动作。相关中文说明与真实验证状态位于 `docs/environment/`。

所有 Testcontainers 用共享清单解析镜像引用。静态检查应扫描测试与 Compose 中是否藏有额外镜像 tag；需要例外时在同一清单登记理由、影响面与回归计划。基础服务尽量复用单一版本；版本对照课才允许少量明确例外，不能每课复制一组镜像。

没有 Docker daemon 时，只能记录语法/配置/模拟命令验证；容器健康、连接、数据读写和停止清理保持未验证。重置会删除实验数据时先明确范围；不得触及真实服务或用户已有卷。
