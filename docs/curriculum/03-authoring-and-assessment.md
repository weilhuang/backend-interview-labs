# 课程制作与验收规范

## 制作原则

课程需要把“知道术语”变成“能够实现、观察、解释与迁移”。每个实验单元必须包含一个明确问题、可运行起点、可区分对错的标准、渐进提示、参考解和迁移练习。课件不是源码目录的说明书，测试也不是让学生猜出作者写法的暗号。

**发布状态分级**：规划 → 编写中 → 作者自测 → 学生预览验收 → 试学修订 → 可用归档。只有通过最后两道门禁才写“可导入、可练习”；本目录描述完整目标；首包 `java-recovery-collections` 已有并行制作的源码，其具体进度单独记录，不等于 15 门完整课程均已完成。

## 私有单仓库与独立课程根

以下是完整体系的目标目录契约；实际首包暂用 `courses/java-recovery-collections` 合并验证 C00/C01 的一部分，构建采用等价的 Groovy DSL（build.gradle/settings.gradle）。不为与示意树一致而强行重命名已可用路径：

```text
backend-interview-labs/
  README.md                       总目录与学习路线，不是 Academy 总课程
  docs/                           课程说明、版本台账、题型/验收规范
  courses/
    00-coding-recovery/
      course-info.yaml
      settings.gradle.kts
      build.gradle.kts
      gradle.properties
      gradlew / gradlew.bat
      gradle/wrapper/
      .courseignore
      common/                     该课归档内能自足的测试/领域 fixture
      section/lesson/task/
        task.md
        task-info.yaml
        src/
        test/
    01-java-collections/           同样是独立根、独立 wrapper/版本信息
    ...
  external-labs/                  按 lab ID 存运行清单、外部脚本与证据规范
  authoring/                      教案规格、答案来源、负例与验收记录
  solutions/                     完整答案与讲解，默认不进入学生归档
  tooling/                       只做协调的验证/打包工具，不冒充 Academy 插件
  releases-manifest/              课程版本、归档校验和、兼容记录
```

根仓库负责导航和维护；学习者在选定的 IDEA 学习环境中打开某一个课程根目录，或导入那一门课的归档。不能仅在根目录写一个 course-info.yaml，把所有不同 JDK/Gradle/服务依赖混成一个课程工程。多个子目录能否被插件自动识别，属于实测项，不能假设一次打开仓库就得到 15 门可切换课程。

跨课公共 fixture 可以由作者工具生成并复制进课内；归档不能依赖 `../../shared`、仓库外软链接或开发者机器的绝对路径。生成来源及版本需要记录，课内副本可独立运行。Go 不套 Java 的 Gradle/JUnit 模型；插件对 Go 的作者/检查支持未验证前，使用原生 Go module 加同样的教案与证据规范。

## 一项任务的内容契约

每个任务在独立教案规格中记录以下字段；这是本仓库自己的规格，不向 Academy 的 YAML 随意添加未支持字段：

| 字段 | 必须回答的问题 |
|---|---|
| ID 与先修 | 学生需要已会什么；提供哪个起点 checkpoint |
| 学习目标 | 一个可观察的能力，避免“了解/熟悉”独立作目标 |
| 场景与约束 | 输入、输出、错误、顺序、并发、资源和禁止事项 |
| 学生可改区域 | 哪些接口可改，哪些是测试契约，是否允许标准库替代 |
| 完成产物 | 实现、测试、证据或说明文件的具体路径 |
| A/O/R/T 分类 | 哪部分自动判分，哪部分观察，哪里是真源码或教学模型 |
| 测试矩阵 | 正常、边界、异常、对抗、恢复；可接受多种实现 |
| 环境假设 | JDK/构建/服务版本，端口、内存、超时和清理 |
| 提示与答案 | 每级提示帮助范围、完整解、另一种正确解、常见误解 |
| 迁移题 | 改一个条件后是否仍能独立做出 |
| 证据与来源 | 官方资料、源码锚点、作者验证记录 |

学生看到的 task.md 先给可执行目标和输入输出，再解释最必要的概念。不要在第一屏倾倒整章理论，也不能把接口或异常契约藏在测试里。理论任务、编程任务和人工证据任务必须在界面上清楚标识。

## 正确性测试与观察实验分开

### 可以自动判分的事项

- 函数返回值、异常类型、指定输出格式、业务状态、资源生命周期
- 固定合同下的集合边界，模型与标准库的差分测试
- 用 latch/barrier/可控调度器驱动的并发交错与业务不变量
- 用假时钟验证 TTL、token bucket、超时预算和状态机；不必等待真实分钟
- 使用真实数据库/队列但有受控 fixture 的集成结果、幂等与 crash point 恢复

测试不得固定 HashMap 无保证的迭代顺序、具体线程调度先后、对象必然回收时点、优化器必须选某索引、某电脑绝对毫秒阈值。需要资源隔离的故障在子进程或实验容器中执行，设置超时、堆/磁盘/并发上限和 finally 清理。

### 应当收集证据并评阅的事项

- 性能快慢、吞吐、P95/P99、JIT/GC 行为、调度观察
- JDK/Spring 的真实源码调用链与版本差异
- SQL 计划选择、锁关系、broker 复制状态、网格路由与追踪采样
- 系统设计与取舍：多个答案可以成立，但必须与约束相容

自动检查器可校验证据包是否完整、字段和关键事件是否存在；这种“证据完整性通过”不等于“结论正确”。不要把答案中包含关键词“MVCC”或“happens-before”判作理解正确。

### 三种运行状态

- **PASS/FAIL**：环境有效，测试确实运行，结论可用
- **BLOCKED/INVALID_ENV**：服务未就绪、工具不匹配、端口冲突、镜像缺失或样本无效，不能记为学生知识失败
- **NOT_RUN/SKIPPED**：用户没运行或选择跳过，不能汇总为绿色全通过

入口预检必须与测试结果分开。预检成功后实验环境仍可能失效，所以集成测试也要保留明确诊断信息。

## 测试质量门禁

1. 起点应能编译并到达预期失败；若题目故意训练修复编译失败，要显式标记，不混入普通题
2. 作者参考解和至少一份风格不同的正确解都通过
3. 每类关键缺陷至少有一个“错误实现”被测试杀死，例如覆盖错位、忘记解锁、重复扣减、吞异常
4. 随机/属性测试有固定种子和可缩减反例；输出足够定位失败
5. 并发测试使用确定性协调；压力测试另列为观察/附加证据，不能拿“重跑直到通过”掩盖 flaky
6. 测试无顺序依赖、无外网硬依赖、无用户目录读写；必要集成服务明确按 profile 启动
7. 不用反射强迫一种私有字段布局；实现型题可以检查算法结构，但必须预先声明要求
8. 保留测试过程日志；不得通过改测试、降强度或跳过失败来宣称完成

## 统一评分而不混淆掌握度

自动正确性和人工评阅分开记录。课程掌握建议使用下面的多维标准；不把它们强行塞进 Academy 的绿色/红色一个状态。

| 维度 | 0 分 | 1 分 | 2 分 | 3 分 |
|---|---|---|---|---|
| 正确性 | 未运行或关键规则不满足 | 仅 happy path | 边界/异常通过 | 新变体与关键失败恢复也成立 |
| 解释 | 复述名词 | 能讲操作步骤 | 能讲机制与前提 | 能用反例界定结论并比较方案 |
| 证据 | 无证据 | 截图但缺环境/过程 | 可复现输入与过程完整 | 对照严谨、排除替代解释、结果有限定 |
| 独立迁移 | 只复制答案 | 需逐步提示 | 少量提示可完成变体 | 不看答案完成新条件并补测试 |

建议完成标准：本单元所有关键 A 测试通过；解释/证据/迁移均至少 2；任何涉及数据丢失、重复业务效果、资源泄漏的核心缺陷未关闭则不通过。需要高等级源码/系统设计能力的课程，再要求对应维度 3。分数是建议评阅工具，不假装为心理测量或招聘评分。

提示使用单独记录 H0–H4，属于学习轨迹，不扣人格化分数。初学时用提示正常，但“提示完成”和“独立通过新变体”不混为一谈。

## 渐进提示与答案处理

- **H0 独立尝试**：给清楚的契约、示例和可运行起点
- **H1 概念定位**：提醒应检查哪个不变量、API 合约或源码入口，不给完整代码
- **H2 反例/步骤**：给一个最小反例、状态表或分解路径，帮助发现自己错在哪
- **H3 局部伪代码**：展示最难的一小步，保留边界与整合由学生完成
- **H4 完整参考解**：包含解释、复杂度/边界、错误解为什么错，以及至少一个可接受替代方案

默认不展示 H4。看过完整解后，要求关掉答案完成迁移题或延后回测，再记录独立状态。答案不能只有代码；复杂题要给因果链。不能故意把题目描述写得含糊来迫使学生点提示。

同一私有仓库里，仓库所有者始终可能查看 answers、分支和 Git 历史。因此答案隐藏只是学习流程，不是安全隔离。`.courseignore` 只能排除指定文件，不能自动抹去题目源文件中的完整解；必须依靠插件实际的答案占位/导出机制，并对学生归档进行泄漏检查。测试若随本地课分发也可被阅读，不能声称“隐藏测试防作弊”。

作者解与学生起点应有单一来源的生成/导出约束，避免分别维护而漂移。每次改契约都要同时更新描述、测试、提示、答案和迁移题。若使用答案分支，记录其与归档的版本对应关系；不以更改仓库可见性控制普通学习提示。

## 真实源码与教学模型的界限

每个 R 任务需要：项目、发布版本、commit SHA、文件路径、类/方法符号、IDE 断点、输入、关键状态截图或文本、推导结论与反例。行号只能辅助，符号和 commit 才是稳定依据。使用对应 sources jar/JDK src.zip；反编译只作为“无法取得源码时的受限观察”，不能标记为原始源码已核对。

每个 T 任务在标题或首段注明“教学实现”，说明未实现的特性。例如 MiniHashMap 只使用拉链、没有树化/并发/序列化；MiniContainer 不提供完整 Spring 生命周期；token bucket 单机模型不保证跨节点全局限额。源码阅读在教学模型后进行对照，而不是把二者混在一个版本里。

不要复制上游大段代码进教材。优先提供官方链接、符号定位和必要的短片段；如确需包含源码文件，遵循对应许可证、版权与 NOTICE，记录来源与改动。

## 外部基础设施混合实验契约

每个实验具备以下内容，且与 Academy Check 分离：

1. `preflight`：版本、CPU/内存/磁盘、架构、端口、容器引擎/集群 context 检查
2. `up`：只启动该实验需要的 profile，资源名带独立 lab ID，不默认拉起所有中间件
3. `seed`：生成/导入合成数据，固定种子，可重入，不接触真实业务数据
4. `verify`：检查 ready、执行已声明测试，结果细分 A 与 O
5. `collect`：日志、指标、配置摘要、版本、命令、时间线、判断；排除秘密
6. `down`：停止本实验资源；删除数据卷需明确选择，保留证据后再清理

这些是待制作的操作入口名称，不保证所用工具都已有同名命令。脚本要先输出目标资源/context；拒绝对生产/未知集群注入故障。不得自动改变防火墙、VPN、账号权限或全局安全设置。昂贵压测、磁盘填充、OOM、网络分区和 broker kill 都需要边界与可恢复环境。

轻量级 Java 任务无需 Docker。MySQL/Redis/MQ 通常按单主题启动；多副本可靠性实验必须真的采用对应拓扑。K8s/Istio/ELK/SkyWalking 分开运行，资源预算待实测，不宣称“所有电脑一键完整启动”。无法运行时可阅读明确标注的参考证据，但课程状态维持真实实验未完成。

## 从试点到全课程的制作顺序

### 阶段一 冻结基础兼容与试点

先制作 C00-01、C00-02、C01-01、C01-04 的垂直切片：讲义→学生起点→测试→提示→答案→导出→全新项目导入。它们分别验证构建/调试、值对象、集合合约和复杂状态，不先铺满所有空目录。

通过后完成 C00/C01 共 16 个单元。收集真实卡点，尤其是忘记语法、看不懂断言、JDK 不匹配、IDE Check 与 CLI 不一致。修正模板后再复制课程机制。

### 阶段二 Java 与框架主线

C02/C03、C04/C05 分批完成。每批独立发布，具备与前批不同的版本清单。源码部分必须在实际目标版本调试一次；不要由模型虚构调用链截图。

### 阶段三 数据与分布式

C06/C07 后接 C08/C09/C10。先完成一个可靠外部实验生命周期，再扩展更多服务。MQ 两条路线可并行制作，但禁止拿其中一种的通过结果代替另一种验证。

### 阶段四 云原生 观测与 Go

C11/C12/C13 各自按兼容与资源矩阵验收，最后汇合 C14。Go 可以提前并行，但不占用 Java 试点的兼容性结论。

## 发布门禁与验收证据

- 课程根独立：干净 checkout/学生归档无需仓库外文件即可构建
- CLI 正例/负例都验证：参考解通过、起点按预期失败、已知错误实现失败
- IDE 兼容：优先在云端验证与用户 IDEA 2026.1.5 匹配的实际 build 和 Academy 插件组合，并试过 Check、提示、重置、导航
- 学生归档：插件创建预览/归档，用全新目录导入；不能只验证作者工程
- 导出卫生：无完整答案意外泄漏、私有数据、绝对路径、缓存、凭据和大体积转储
- 外部实验：从空环境到执行到清理全部验证；资源不足/服务未启动不伪记 PASS
- 内容核对：契约、代码、测试、hint、解答、source anchor 同一版本
- 发布记录：课程版本、template commit、依赖锁、归档 checksum、操作系统/架构与已验证组合

只有这些记录齐备，才把课程状态改为可用。为一个版本提供确定的兼容范围，比给所有软件贴“最新版”更重要。
