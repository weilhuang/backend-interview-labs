# 14 天面试优先路线

## 这条路线的作用

在完整课程不缩减的前提下，先恢复写代码和解释核心问题的能力。它是优先顺序，不是承诺两周学完 105 个单元。每天时间未知，因此只定义核心块、可选块和当日证据；不假设每天能投入 8 小时，也不把每一天塞成一个完整技术栈。

以下使用 D1–D14，不擅自把准备开始日等同于本文日期。每天至少保留「自己写 → 测试 → 解释」闭环。题目读懂后先独立尝试，再按级别打开提示；开过答案的题另找变体回测，不直接计为独立掌握。

制作与验收优先在云端完成；学习者可在 IDEA 导入课程，重型服务可远程部署，具体学习运行方式另行选择。所有 ID 对应[完整目录](01-full-curriculum.md)。一天写多个 ID 表示从这些单元中选代表场景，不表示当天完成了这些整门课程。代表场景只是本轮优先学习；未做的实验仍在完整课程中等待后续完成。

## 每天通用的核心块结构

1. **取回记忆**：先不看讲义，讲出昨天的关键不变量或修复思路；卡住再查
2. **完成一个小而完整的实现**：从明确接口、测试或故障开始，不靠大量复制已有答案推进
3. **补一个反例**：空值、边界、取消、重复、超时或失败恢复，至少一个
4. **解释证据**：用 2–5 分钟说清为什么正确、哪里不保证、生产条件会增加什么
5. **记录下一步**：记一项最具体的未掌握点，不把整门技术写成“不会”

每日投入较少时完成这个闭环即可；不必追赶表格里的可选块。若某个核心实验跨度大，保留进度到次日并把较低优先级主题后移。

## 三个检查点与调整规则

### D2 编码恢复检查

不用答案完成解析/聚合变体，能通过测试定位一处缺陷。若失败，D3 的核心块继续 C00，把集合源码阅读后移；不能通过跳过基础来制造“进度”。同一问题连续卡住时先用小接口或可运行 fixture 降低环境负担，不降低正确性要求。

### D7 Java 核心检查

随机抽一个集合题、一个线程池/取消题、一份 JVM 证据。要求讲清机制和边界。若只会背术语，从 D8–D9 的可选块借空间复练，不把没做过的源码题计为掌握。

### D12 数据与可靠性检查

能够画出 MySQL、Redis、MQ 三种失败时间线，并说出每个持久化/提交点。若 Docker/网络问题占用时间，可先完成纯逻辑模型和阅读已标注的示例证据，但真实集成状态保持“未验证”，不能以模型通过替代实测通过。

## 岗位侧重调整

- **常规 Java 业务后端**：核心顺序保持；优先 C00–C10，D13–D14 以一个可靠项目串联
- **中间件/性能岗位**：从可选块提高 C02/C03、真实源码、MySQL/MQ 故障与性能分析权重
- **云原生/平台岗位**：先保留编码与事务基础，再把 D13 的可选块改成 C11/C12 主块；需要延后其他主题，不宣称凭一天掌握 K8s/Istio
- **Java＋Go 岗位**：Go 是独立完整课；用岗位权重替换部分低优先级可选块。两周内不把 Go 速记当作完整 Go 服务能力

这些是可选调整规则，不是对用户目标岗位的假定。只有岗位信息明确后才改路线。

## 面试前的成果清单

- 一个不查答案能改需求的 Java 小项目
- 一份真实 JDK 或 Spring 的源码调用链，带版本
- 一次并发或 JVM 故障的复现与修复
- 一次真实 MySQL 事务/索引实验
- 一个 Redis/MQ 的失败窗口与恢复说明
- 一份诚实的知识状态：独立完成、提示完成、答案后回测、只阅读、未开始

最后两类状态不丢人，也不伪装成实际经验。两周之后按[完整课程目录](01-full-curriculum.md)补完剩余单元，课程标准、源码深度和基础设施实验范围保持不变。
