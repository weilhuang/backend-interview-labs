# 编码恢复与集合试点详细设计

## 内部试点包与完整试点的关系

内部试点不是正式 V1 完成。V1 必须按[分版计划](08-release-plan.md)覆盖完整 Java、框架、数据库缓存、消息队列与分布式体系。

完整目标是 C00 的 8 个单元加 C01 的 8 个单元，共 16 个单元。当前先行实现采用一个合并课程根 `courses/java-recovery-collections`，含 12 个编程任务，用于尽早验证 Academy 工作流和恢复手感。**12 个任务不是把 16 个完整单元删成 12 个；两者粒度不同，内部试点包也未覆盖完整试点的全部目标。**

本文件于 2026-09-30 只读核对了内部试点包的 course-info.yaml、build.gradle、gradle.properties、wrapper 配置和各 task.md；下表描述可见源码与配置，不宣称所有任务已经运行或已通过 IDE 导入。初轮代码验证由内部试点包制作方报告 65/65 JUnit checks 通过、12 个学生空实现和12 个错误变体均被拒绝、12 任务/20 个 UTF-16 占位静态有效；该轮用裁剪环境中 javac 21 组件执行 -source 17/-target 17，尚未验证 --release 17 的 API 兼容、Gradle 或 IDEA。运行、作者答案、学生起点、插件导入仍分别以内部试点包最终验收记录为准。

## 统一学习场景与脚手架

完整试点扩展使用合成订单数据，字段只含订单 ID、SKU、数量、单价和状态，不读取真实个人/公司数据。先行 12 题保留自己的已声明契约；下面的完整场景是后续教案设计，不悄悄改变内部试点包题目的边界。

- 基础模型：订单不可变；金额以分为内部单位，十进制解析必须精确，数量为正
- 文件格式：明确为教学用简单分隔文本；不支持引号/转义时直接声明，不假称完整 CSV 解析器
- 重复订单：完整项目采用“重复 ID 为数据错误”；稳定去重题则按它自己的合同处理，不能混用
- 输出：按指定键稳定排序；测试不依赖哈希表内部顺序
- 校验：每题定义 null、空值、非法值的异常和校验顺序；需要失败不改状态的地方明确要求
- 起点：按任务提供编译可通过的接口/待实现方法；已完成前置功能用 fixture 提供，不使后题依赖学生前题的 bug

## C00 八个完整单元的制作规格

### C00-01 环境与第一个红绿循环

**产物**：一份环境摘要、一项主动修复的 JUnit 测试、一段断点记录。

**起点**：一个不依赖网络服务的加总方法与失败测试；构建依赖首次获取与题目逻辑分开。先在云端可用的 IDE 验证环境检查能打开课程根，再验证 CLI 与 Check 的行为。

**A 测试**：0 个输入、单个输入、多输入、非法值；故意错误实现至少触发一个明确断言。构建失败不能算作正确的“红”。**O**：学生指出 SDK、Gradle JVM、测试 JVM 各是什么；说明哪里进入被测代码。

**提示**：H1 看 expected/actual；H2 用最小输入追踪累加器；H3 画循环初始/终止状态；H4 给完整修复及为什么原错。**迁移**：把空输入合同从 0 改为异常，独立修改实现和测试。

### C00-02 值对象与金额

**产物**：Money/OrderId、输入转换与错误策略，另用内部试点包 money-total 复练聚合。

**合同**：Money 内部为 signed long 分，金额字符串必须能精确转换为两位小数；单价/订单金额的非负规则属于订单验证。`1.0` 与 `1.00` 是同值；不得经 double 转换；超出 long 范围或非精确分转换须抛声明的异常。把领域非负与数学表示分开。

**A 测试**：0、1.0/1.00、负值在 Money 与 Order 两层的不同规则、超过两位小数、null/非法字符串、加乘溢出、equals 对称/传递/hash 一致。**O**：说明 BigDecimal equals/compareTo 的不同，以及为什么内部单位和舍入规则是合同。

**提示**：H1 金额不是浮点近似；H2 把输入换成整数分；H3 看精确转换与溢出检测 API；H4 完整解与 BigDecimal 备选。**迁移**：增加一个不同小数位币种时，先指出当前模型不适用再设计变更，不能默默用相同规则。

### C00-03 解析 校验与错误定位

**产物**：从行文本得到 Order，含行号/字段的错误报告。先用内部试点包 parse-ids 学边界，再扩展订单行。

**合同**：固定字段数、明确空白/大小写策略、保留空字段；任何输入错误不生成半成品订单；批处理选择 fail-fast 或收集所有行错误并写清，不混搭。

**A 测试**：空行、尾部分隔符、缺字段/多字段、数量 0/负值/溢出、未知状态、重复 ID 与首个错误位置。**O**：异常在哪层转换、不能吞掉原因。

**提示**：H1 分清分割与领域校验；H2 尾部空 token 反例；H3 按 parse→validate→construct 排列步骤；H4 完整解。**迁移**：新增可选字段但保持旧格式可读，补兼容测试。

### C00-04 泛型 排序与聚合

**产物**：类型安全 repository、订单分组/稳定排序，循环与 Stream 两种实现。

**A 测试**：原列表不变、空数据、比较器并列、计数与金额聚合、明确 null 策略；两种实现做差分。**O**：Comparator 传递性、泛型上下界、副作用与串行/并行流边界。内部试点包 bounded-stack/top-words 可作子任务，但不替代整个目标。

**提示**：H1 明确每一步输入输出类型；H2 并列数据触发比较器问题；H3 给 map/group/reduce 结构；H4 两种完整解与取舍。**迁移**：改变排序主次键，独立保证结果稳定。

### C00-05 IO 与资源清理

**产物**：从课程 fixture 路径读订单、输出报告、记录坏行；不接受任意用户目录作为默认测试数据。

**A 测试**：UTF-8、空文件、末行无换行、读取中失败、输出失败、资源只关闭一次；用可观察资源替身测试关闭路径。**O**：try-with-resources 与异常覆盖/suppressed exception。

**提示**：H1 谁拥有资源谁负责关闭；H2 让读取器在第二行抛异常；H3 给资源范围结构；H4 完整实现。**迁移**：从 Reader 而不是路径接收输入，解释为什么更好测。

### C00-06 三个独立调试事故

**产物**：索引边界、可变别名、异常遮蔽各一个“最小失败→定位→修复→回归”记录。

**A 测试**：修复前确实失败，修复后通过且没有改测试；新增测试能杀死原错误实现。**O**：断点、变量/调用栈与因果链，不接受“IDE 提示这样改”作为原因。

**提示**：H1 列出首次状态偏离；H2 缩小输入；H3 指向关键语句；H4 故障解释。**迁移**：换一组输入或相邻边界，排除修复仅适用于样例。

### C00-07 常见编码模式

**产物**：每种模式一个可独立打开的小问题：哈希计数、滑窗、二分边界、栈队列、树 BFS/DFS、简单 DP。它们是一组训练，不强行放进同一道长题。

**A 测试**：固定样例、空/重复/极端边界、固定种子小规模对暴力 oracle；对很大的输入只检查合理的算法结构与有界运行，不测电脑竞速。**O**：给出循环/状态不变量、复杂度和溢出边界。

**提示**：先提醒模式，再给不变量，再给递推/循环骨架；完整答案之后换条件重做。**迁移**：至少两题在改变数据范围或返回要求后独立实现。

### C00-08 订单分析 CLI

**产物**：端到端输入校验、过滤、聚合、稳定报告；一页运行与设计说明。

**A 测试**：同一输入重复运行相同结果、非法输入退出状态与错误信息、输入未被意外改动、资源清理、金额/排序合同；不可只测 main 的一行输出。**O**：学生现场增加一个过滤条件并解释影响层。

**提示**：优先组合已存在的小模块，不能为赶进度重写成一个大函数。**迁移**：替换输入方式而不改核心聚合。内部试点包 recent-ids 是更小的组合训练，不能据此宣称 CLI 已交付。

## C01 八个完整单元的制作规格

### C01-01 集合语义与别名

**产物**：稳定去重、结构快照、视图行为测试与集合选择说明。

**A 测试**：原列表 set/clear 对结果影响；快照可修改性；内部元素可变时浅拷贝边界；List.of、Arrays.asList、subList 和包装视图各自的声明合约。**O**：不修改结构、结构独立、元素不可变是三个不同性质。

**提示**：H1 结果是否与原数据共享结构；H2 修改原列表与修改元素分开试；H3 先复制再限制修改；H4 多种实现及 null 差异。**迁移**：从快照改为动态只读视图，解释不同用途。

### C01-02 MiniArrayList 与真实 ArrayList

**产物**：只用数组存储的动态数组、变异测试与真实源码路线。

**A 测试**：0 容量、跨扩容边界、首/中/尾删除、错误后状态不变、返回旧值、尾槽释放引用；可在教学结构中使用包可见诊断接口，不反射强迫 JDK 私有布局。与 ArrayList 差分仅比较共同合同，不比较容量策略。

**R/O**：用目标 JDK src.zip 记录 add/grow/remove 的入口和状态；解释教学“翻倍”和实际增长策略未必相同。**提示**：先 size/capacity 不变量，再数组搬移图，再局部伪码，最后参考实现。**迁移**：补一个已声明的 insert 或 removeRange 子集。

### C01-03 链表与 deque

**产物**：双向链表 add/remove 小子集、ArrayDeque 的 BFS 或滑窗任务。

**A 测试**：空/单节点/首尾删除、prev/next 对称、size、无孤立仍被索引节点；使用固定种子操作序列。**O**：定位与修改分别计算成本，解释为何随机访问不适合链表。

**提示**：画四个指针，再按空/首/中/尾分类，最后给 splice 伪码。**迁移**：将一段使用旧 Stack 的代码换为 Deque 并保持异常合同。

### C01-04 MiniHashMap 与身份契约

**产物**：明确支持 null key/value 的单线程拉链 map，包含 put/get/remove/containsKey/size 与扩容。

**A 测试**：相等键覆盖返回旧值、同 hash 不相等、值为 null 与不存在区别、链头/中/尾删除、跨多次扩容后仍可找回、固定种子对 HashMap 差分；精心设计 hash 值覆盖负值与高位变化。

**O**：指出未实现树化、视图、迭代器、并发和序列化；可变 key 只作为使用错误反例，不要求 map 自动修复。**提示**：H1 hash 与 equals 分工；H2 构造同桶两键；H3 指向遍历/覆盖/新增三分支；H4 完整链式解。**迁移**：新增 putIfAbsent 时先定义 null 值语义。

### C01-05 真实 HashMap

**产物**：固定版本的 hash→putVal→resize/treeifyBin→getNode 路线，带一组受控碰撞 key 与关键状态。

**A 测试**：公共 map 合同、扰动/索引数学子题；内部试点包 hash-index 属于这一部分。**R/O**：用目标源码说明容量、阈值和树化条件，实际进入的分支与预期对照；没有进入预想分支时记录原因而非伪造截图。不可因单次实验没看到退化就断言永不发生。

**提示**：H1 从插入入口开始；H2 比较 table 长度和桶节点数；H3 给断点符号而不直接给结论；H4 完整路径图及目标版本阈值。**迁移**：改变初始容量，先预测再运行并解释分支变化。

### C01-06 TreeMap PriorityQueue 与 LRU

**产物**：时间范围检索、top-K 和单线程 LRU 三个契约明确的小任务。

**A 测试**：范围开闭边界、比较器并列/极值、k=0/负数/大于长度；LRU 命中/未命中/更新/淘汰/快照。**O**：TreeMap 比较器定义键等价，PriorityQueue 的迭代不排序，LRU 访问順序不等于插入顺序。

**提示**：先画需要的顺序，再选择结构，再给最关键 API。**迁移**：把 top-K 从静态数据改为流式到达，解释空间和维护成本；不要求所有问题共用一种实现。

### C01-07 Iterator 与并发集合边界

**产物**：安全删除、CopyOnWriteArrayList 快照、ConcurrentHashMap 原子计数的三个最小实验。

**A 测试**：单线程 iterator.remove 的合法/非法调用次序、快照中旧序列、join 后的最终计数；并发误用的测试只证明特定受控交错，不能依赖它必然抛 ConcurrentModificationException。**O**：尽力 fail-fast、弱一致迭代、快照各自含义。

**提示**：H1 谁负责结构修改；H2 用连续两个待删元素击穿错误循环；H3 iterator 状态图；H4 正解与 removeIf 备选（仅当该题不要求练 Iterator 时）。**迁移**：从单步 map 更新变成跨两个键业务不变量，指出单键原子 API 不足。

### C01-08 集合选型与综合迁移

**产物**：订单索引、top-K 与 LRU 组合；JMH 实验规范与结果解释。

**A 测试**：功能契约、输入不变、边界与组合后不变量；不以速度阈值决定正确性。**O**：JMH 预热/fork、死代码消除防护、输入分布、操作比例、分配率和误差；同时提交至少一种“结果不足以下结论”的说明。

**提示**：先保证等价工作量，再测量。**迁移**：改为写多读少或大对象 key 后重新做选择，不沿用旧结论。**出口盲测**：无答案完成一个集合需求、一项边界修复、一段真实源码解释。

## 试点专用验收清单

1. 先验内部试点包全部 12 题的接口、测试、提示与学生起点；任务名、路径不因规划更完整而被悄悄更换
2. 正确解通过，典型错误解失败；不要只看已完成答案的全绿
3. 制作方优先在云端完整 JDK 与目标 IDEA/Academy 组合下分别验证 CLI 和 Check；学习者使用本机还是远程 IDE 另选
4. 用插件导出的学生预览/归档从新目录导入，核对学生起点、提示、重置，以及标准解/解释、调用入口和所有测试均可读
