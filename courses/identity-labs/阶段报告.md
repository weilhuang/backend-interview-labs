## 具体教什么

第一层是“登录成功以后还要判断什么”。学员区分认证与授权，把 Subject、Resource、action 组合成 Decision。reader 可以读取；editor/admin 可以读取和审批；所有角色均受订单租户约束。admin 不能跨租户，也不能自动获得未知动作权限。

第二层是“拒绝原因与顺序也是合同”。认证缺失先返回 `UNAUTHENTICATED`；资源或租户属性缺失返回 `MISSING_ATTRIBUTE`；随后依次检查 `TENANT_MISMATCH`、`UNKNOWN_ACTION`、`ROLE_DENIED`，最后才能 `ALLOW`。教学不只检查布尔值，也检查固定 reason、空白输入、默认拒绝和角色集合不可变性。

第三层是“身份可信从哪里来”。讲义区分 cookie、session、access token、ID token 与 refresh token；解释 JWT 的编码、签名、issuer、audience、有效期、JWKS、kid 与密钥轮换。资源服务源码固定信任配置中的 JWKS 地址，用成熟 JOSE 库完成 RS256 验签，再验证声明；调用者自报的角色头和租户头不作为权限来源。

第四层为后续 LDAP 与 Keycloak 实验打基础：OAuth 2.0 与 OIDC、授权码、state、nonce、PKCE、精确 redirect URI、BFF 与 CSRF；LDAP 的 DN/RDN、搜索范围、filter 转义、bind、TLS、唯一结果与超时；Keycloak 的 realm/client/role，以及联邦、导入、缓存、同步和撤权窗口。浏览器登录回调、真实目录登录与联邦生命周期在本阶段尚未实现。

## 谁调用学员代码

`Usage.main` 直接调用 `Policy.authorize`，给出同租户读取、reader 审批和跨租户读取三个可手算例子。公开 Policy 测试直接调用同一接口。

完整服务的源码调用链是：课程前端发 HTTP 请求 → Spring Bearer 认证过滤器 → JWT provider → `IdentityTokenDecoder` / `NimbusJwtDecoder` → `TrustedSubject` 从已验证 JWT 选择当前租户角色 → `OrderController` 从服务端仓库查订单真实租户 → 学员 jar 中的 `Policy.authorize` → 返回结果或在修改状态前拒绝。

构建配置只把学员 `src` 编译进学员 jar；服务依赖这一个 jar。标准答案与错误解均在生产 sourceSets 外。代码中另有运行期 CodeSource、类资源数量和 jar 内容断言，等待实际 Java 验证唯一加载来源与答案隔离。

已提供[中文页面](materials/identity/identity-lab/src/main/resources/static/index.html)和[请求代码](materials/identity/identity-lab/src/main/resources/static/app.js)。页面提供读本租户订单、审批和尝试跨租户访问三个按钮，只暂存本地合成 token 到页面内存，不要求学员编写前端。它不是 SSO 登录页；浏览器交互尚未验收。

## 当前证据与严格门禁

已完成的检查仅限 Python、源码静态检查与合成证据回归：11 个顶层 Python 测试通过；完整形状 mock 对照可接受，38 个负探针被拒绝。独立复审又复现原 9 类假通过反例，并增加 2 个旧回执反例，均被拒绝。这里的 mock 只替换执行进程并生成测试数据，没有启动 Java、Gradle 或 HTTP，不能据此推断服务已运行成功。

实际执行脚本要求每个场景在新隔离目录中运行，绑定 run ID、源码、配置、工具入口和固定依赖锁的 hash，禁用缓存并强制重跑。它联合检查精确 XML suite/method、Gradle 执行回执与 HTTP 状态观察值，拒绝零执行、旧证据、跳过、额外异常、编译失败、超时和缓存命中。

学员测试的 `finalizedBy` 接到服务 `httpAcceptance`。两个正确参考场景必须全部成功；负场景仅接受专属订单断言 `expected 200 / actual 401` 这一项失败，其余方法全部成功，且 Gradle 整体退出码为 1。实际 Gradle hooks、XML 格式与 finalizer 失败传播仍待首次运行确认。这套证据链依赖可信工具链与测试源码，不是针对恶意执行器的远程证明。
