## 三、代表机制与题目

### 旧回填不是一句“删缓存”能解决

```text
A读v1暂停 -> B事务提交v2+事件 -> 删除缓存 -> A回填v1
事件重投 -> floor提高到2并失效 -> 晚到v1被拒绝
Redis水位灾难丢失 -> 停流 -> 从数据库重建 -> 再开放
```

测试能显示错误窗口、重投幂等、恢复后的最终值，并明确水位无TTL仍会因allkeys淘汰/灾难丢失。没有调用恢复器、服务永久不可用或不遵守版本协议时不承诺有界收敛。

### 租约与fencing不是同一个保证

面试题：旧持有者过期后恢复才领取fence，是否安全？答案：不安全，反而可能领到更新序号骗过资源端。本课包含该错误路径真实接收的反例，并将正确授予封装为先发持久序号、再获取Redis租约、固定绑定FencedLease，资源端条件写拒绝旧代次。序号浪费可接受；序号回退不可接受。

### 背压必须覆盖未真正结束的工作

一个回源忽略中断，Future虽已取消，它仍占工作线程；零等待队列的新请求立即拒绝。测试以latch控制释放，检查activeOriginTasks、rejected、timedOut，不用扩大线程池掩盖慢依赖。
