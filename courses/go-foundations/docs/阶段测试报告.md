## 交付内容与学习入口

这是第二版的 Go 基础三课独立源码，尚未接入唯一主课程，不是完整第二版，也不是正式 Academy 课程包。

## 新增 Go Actions 的范围

本阶段提出独立 Go 验收工作流：仅在本目录或该工作流文件变化时触发；使用 ubuntu-24.04、固定 Go 1.27.1 和官方归档校验和，原样调用现有 test_static.py 与 verify.py，不修改验证器。

工作流只保存日志和 JSON，不上传 SDK、缓存、工作副本或课程包；失败时也尝试保存证据。环境准备失败、超时或 race 工具链缺失均不能算通过。相同 PR 的新提交会取消旧的 Go 作业，既有仓库门禁保持不变。

Go 独立工作流已在提交 c3b655be4e740f678f994df1c190ac8457bdaf8d 的[首次运行](https://github.com/weilhuang/backend-interview-labs/actions/runs/36947096857)通过：9 项静态测试和 54 项 Go 检查全部通过。下载的证据包中 138 个原源码哈希与已核源码一致，运行前后未变；实际测试合并提交 f23c0e2895adf7f4086d32bb7c4b008e7737a250 与该 head 文件树一致。同期[既有分层 CI](https://github.com/weilhuang/backend-interview-labs/actions/runs/36947097143)的 15 个 job 也全部成功。后续提交仍须查看其自身 Actions job 与 ci-execution.json。原验证器 verification.json 中的 github_actions 字段保留本地执行语义，不单独代表 Actions 状态。

## 公开 JUnit 检查桥

同一批 138 文件另完成本地公开桥实测：27 个场景，每场景 3 个 JUnit 测试、0 跳过。六个正确答案通过，三个 starter 和 12 个练习区错解触发真实业务失败；三个 Go 不可用和三个语法错误属于环境/编译拒绝控制，不能算业务反例。

本地使用 Java 21 和 JUnit Platform Console Standalone 1.11.4。该环境的裁剪 JDK 缺少 ct.sym，首次 --release 21 编译准备失败；随后同一 Java 21 编译器使用 -source 21 -target 21 完成上述实测。这个限制与替代结果分别保留，不能称已验证完整 JDK 的 --release 21 路径。

本次新增公开 scripts/verify_public_bridges.py 和 Actions 接入提案：使用标准 Temurin JDK 21 的 javac --release 21、固定 JUnit 归档校验和，重现上述 27 场景，不提供裁剪 JDK 降级路径。验证器另有 16 项不运行 Java/Go 的普通回归已通过，覆盖错误 JUnit 套件、漏课、重复错解、旧 XML、错误失败目标、环境错误和 Python 优化模式拒绝；这些不是桥的真实运行结果。该新增路径在报告编写时尚未运行；以对应提交后续 Actions 和 bridge-ci 证据为准。

## 手动复验入口

进入 courses/go-foundations，准备 Python 3、PyYAML 6.0.2 和官方 Go 1.27.1；设置 GO_EXECUTABLE 为真实 Go 编译器绝对路径后运行：

```sh
python scripts/test_static.py
python scripts/verify.py
```

race 验证还需要可用的 C 编译器。验证只在本目录 work 和 evidence 下生成工作副本与日志，不修改作者源。

完整 JDK 21 下复验公开桥，还需将 JAVA_HOME 指向 JDK 根目录，并将 JUNIT_CONSOLE_JAR 指向固定的 JUnit Platform Console Standalone 1.11.4 文件：

```sh
python scripts/verify_public_bridges.py
```
