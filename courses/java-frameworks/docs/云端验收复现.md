# 云端验收复现

本文件给课程制作方复现命令，学习者只需正常JDK21和Gradle课程环境。不要在用户Mac上执行这些制作任务；也不要把测试完成自动解释为可以合并或发布。

## 基础运行

```bash
./gradlew test verificationClasspath :03-transactions:compileIntegrationTestJava
python3 authoring/validate_course.py
python3 authoring/verify_callers.py --jdk "$JAVA_HOME"
```

作者静态工具使用Python3与PyYAML6.0.3。Java源已格式化；不要在有人手工编辑输出项目后盲目重跑初始生成器覆盖修改。格式化工具和独立JUnit控制台的版本、摘要见authoring/tools-lock.json，工具JAR不随课程分发。

## 已知错误实现的回归

```bash
python3 authoring/verify_negative_cases.py \
  --jdk "$JAVA_HOME" \
  --console /已核验的/junit-platform-console-standalone-1.12.2.jar
```

每个负例先用--release21编译；编译失败不会计作“被正确性测试拒绝”。再使用同一套公开JUnit测试，必须实际出现失败断言。新手起点和17个错误实现全部公开在作者规格中；没有隐藏业务合同的私有测试。

## 真实MySQL

```bash
# 可选覆盖；本课程shared快照支持无父仓库读取
# export LAB_SHARED_VERSIONS=/实际仓库路径/infra/versions.env
./gradlew :03-transactions:integrationTest
```

这一步需要可用Docker。编译integration-test或解析依赖不等于运行过MySQL。镜像与其他课程同源，Testcontainers固定1.20.6，不另建版本台账。

## 浏览器

先在支持浏览器进程的云端启动02阶段，再运行：

```bash
node authoring/verify_frontend.cjs
```

当前脚本在编写时使用Playwright1.62.1 API；LAB_CHROMIUM可指定环境里已安装且授权使用的浏览器路径。不得为通过测试绕过系统安全限制。当前云命令沙箱拒绝Chromium的Unix socket创建，因此这组真实UI检查仍未执行。现有脚本覆盖创建、重复、冲突、按钮忙态、网络失败、超时、旧响应竞态和窄屏截图。

## Academy

最后在目标IDEA2026.1.5与兼容Academy中打开独立课程根，创建学生预览，检查真实题面/占位/标准解/所有调用方与测试。执行错误与正确答案的Check、重置，然后用插件导出并在干净目录导入。普通源码ZIP或authoring/materialize_learner.py生成的Gradle副本都不能称为原生课程归档。
