## 第一章：恢复写代码的能力，同时恢复契约意识

### 01 金额累计

练习long、记录类型、枚举、循环、输入校验和精确加法。不是只求一个sum：未付款订单仍要校验；空列表返回0；null、负数、溢出分别有明确失败行为；调用不得修改输入。

代表反例：Long.MAX_VALUE和1都是合法单笔非负金额，但累计必须失败，不能悄悄变成负数。参考解使用Math.addExact，并要求能解释普通+与精确加法的差异。

[题目、完整答案和解释](java-pilot/01-recovery/01-money-total/task.md) · [完整调用端](java-pilot/01-recovery/01-money-total/src/labs/PaidTotalsUsage.java)

### 02 ID解析

练习从外部文本到业务身份的转换。“03”和“3”解析后是同一个ID；必须保留首次出现顺序；"1,"不能因为split默认丢弃结尾空串而被接受。测试覆盖符号、非ASCII数字、0、溢出、连续/首尾分隔符和可变返回列表。

### 03 泛型有界栈

练习泛型、Deque、Optional、容量边界和失败原子性。push(null)即使在满栈时也先报null错误；满栈失败不能丢掉原元素。面试表达要区分业务容量、底层数组容量和线程安全。

## 第二章：把集合接口的细节写成可观察行为

### 04 稳定去重

要求保留首次出现的对象实例、输入顺序以及一个null；输出是独立可变List。专门构造相同hashCode却不相等的对象，防止把hash碰撞误判为重复。解释LinkedHashSet为什么同时满足顺序与查重，以及预期复杂度的前提。

### 05 不可变Map键

tenant与userId共同定义身份。测试两个不同String实例的同一文本、不同tenant、不同ID、不同类型、null及真实HashMap查询。强调相等对象必须同hash，不相等对象可以碰撞；final引用并不自动带来深不可变。

### 06 确定性词频Top-K

规范化采用Locale.ROOT；按次数降序、词自然序升序。测试在土耳其语默认Locale下重复执行，验证结果不依赖机器语言。先写清楚完整排序，再讨论小k大m时的堆优化，避免为了背复杂度忽略平票规则。

### 07 视图与结构快照

直接让调用端在生成快照后修改并清空原列表，观察返回结果。测试既证明结构独立与不可修改，也证明元素没有被深拷贝。这个区别常见于API返回值和跨层数据传递，不能只背“List.copyOf不可变”。

```text
subList视图 --> 仍关联原列表结构

copyOf快照 --> 独立列表结构 --> 仍是原来的元素对象
```

### 08 安全原地删除

练习Iterator协议而非记一句“遍历时不能删除”。先完整校验null以保证失败前不变更；通过同一个Iterator删除连续负数。源码讲解cursor、lastRet、expectedModCount与modCount，继续追问为何ArrayList的正确迭代删除仍可能是O(n²)。

## 第三章：从小型实现走到JDK源码证据

### 09 动态数组

实现IntVector的追加、按下标读取、保持顺序删除，区分size和capacity。先用小数组手算，再用固定随机种子与ArrayList模型作1200步对照。教材中的翻倍策略明确不是JDK ArrayList完整复制；要求对比JDK的默认容量与增长分支。

```text
[1][2][3][4]          size=4, capacity=4
追加5后
[1][2][3][4][5][ ][ ][ ]  size=5, capacity=8
删除下标1后
[1][3][4][5][ ][ ][ ][ ]  size=4, capacity=8
```

面试解释必须同时讲出：一次扩容O(n)、连续追加均摊O(1)、空间预留和峰值复制成本，而不是只报一个O(1)。

### 10 HashMap扰动和桶索引

标准答案的核心很短，教学重点在于解释前提：

```java
public static int spread(int hash) {
    return hash ^ (hash >>> 16);
}

public static int index(int hash, int capacity) {
    if (capacity <= 0 || (capacity & (capacity - 1)) != 0) {
        throw new IllegalArgumentException("容量必须为正的2次幂");
    }
    return spread(hash) & (capacity - 1);
}
```

上面是报告中的讲解片段，完整工程实现与测试见题目文件。解释>>>为什么对负数重要，以及2次幂容量为何可以取低位。固定随机测试5000组hash验证扩容后新桶只可能为旧桶j或j+oldCapacity。

源码实验明确定位OpenJDK21的hash、putVal、resize、treeifyBin：比较初始容量16与64，逐次插入碰撞键并记录链表/树/扩容状态。TREEIFY_THRESHOLD=8并不等于任何路径上“第8个元素必定树化”，需要看计数与MIN_TREEIFY_CAPACITY分支。

[题目、固定源码入口与答案](java-pilot/03-internals/10-hash-index/task.md) · [完整调用端](java-pilot/03-internals/10-hash-index/src/labs/HashIndexUsage.java)

## 第四章：组合数据结构，明确业务语义

### 11 LRU缓存

完整调用序列为put(a)、put(b)、get(a)、put(c)，容量2，必须淘汰b。覆盖已有键也刷新访问顺序，未命中不刷新，快照不能暴露活动视图。面试追问聚焦“成功get也会改链表”，不能把它误当成可并发无锁的只读操作。

### 12 近期ID去重窗口

组合Deque和Set，保持两者元素集合相同、无重复且不超容量。重复请求不刷新顺序，被淘汰ID允许重新接受。容量2时a,b,a,c,a的结果应为true,true,false,true,true。固定随机种子与简单模型作4000步对照，检查组合状态的一致性。

这节继续连接后续分布式与MQ课程：窗口去重不是永久幂等，更不是跨进程exactly-once；必须继续讨论幂等键、TTL、状态持久化及业务写入的原子边界。

## 代表性面试问答：不是背概念，而是递进追问

以快照为例：

1. 机制：为什么unmodifiableList不是快照？参考表达：它只是限制通过包装器修改，仍委托底层集合，其他引用修改底层时内容可能变化
2. 边界：区间外存在null为什么不应失败？参考表达：本题只承诺选中区间不含null，校验不应无依据扩大范围
3. 取舍：为什么不深拷贝所有元素？参考表达：通用List API不知道任意对象的复制语义与成本，必须由领域模型决定
4. 追问：跨线程发布一致快照怎么做？参考表达：需要受控的快照获取过程与安全发布机制，copyOf本身不是并发协议

以近期去重为例：

- 为什么需要队列和集合？队列管理先后，集合避免每次线性查重
- 重复请求为什么先查再淘汰？否则拒绝的请求也会破坏窗口
- 为什么淘汰时必须删两个结构？只删队列会让集合保留陈旧ID，后续请求被错误拒绝
- 用Redis的SETNX就能声称业务exactly-once吗？不能，还要说明与业务效果的事务边界和失败恢复
