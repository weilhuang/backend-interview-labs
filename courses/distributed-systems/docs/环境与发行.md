# 环境、恢复与发行

## 普通学习环境

使用JDK21与随附Gradle Wrapper。网络需能访问Maven Central和Gradle分发服务。运行端口由系统动态分配且限定回环；无需修改防火墙、系统代理、VPN或用户Mac。

`./scripts/course.sh doctor`只检查环境，不安装软件、不创建持久账号。`test`运行本机RPC与SQL合同快测；`integration`启动隔离Testcontainers并在try-with-resources退出时清理。失败时先检查测试XML和异常原因，不能自动将缺服务跳过当成功。

## 云端验证路径

当前dot云端没有Docker daemon，因此只可记录JDK编译、真实本机网络与不依赖Docker的测试。Java直连官方仓库遇到证书链/代理限制时，作者脚本通过环境已有HTTPS代理获取官方原始POM、Gradle .module元数据和JAR，保存为本地只读Maven仓库，再供Gradle使用；没有关闭TLS检查或更改系统网络配置。

`authoring/prefetch_gradle_metadata.py`先补齐锁定坐标的官方元数据并记录来源/SHA256；本地Maven配置与Central均保留Gradle元数据重定向，禁止使用POM-only解析结果制作正式锁。`verificationClasspath`会解析所有模块的main/test/integration编译与运行六类配置，即使某配置暂时没有源码。`authoring/resolve_cloud_dependencies.py`仅用于作者云端固定工具路径复现，不是普通学员运行要求；课程默认仍为Maven Central。工具缓存与构建日志不进入课程归档。

## 真实Docker验证

GitHub工作流`.github/workflows/distributed.yml`在Ubuntu Docker runner执行全部单元与integrationTest，必须等待这批提交对应的实际CI结果，工作流存在不等于集成通过。MySQL、Redis、Kafka均读同一个`infra/versions.env`，不允许在测试源文件内重新写镜像版本。

Testcontainers可能使用辅助镜像；若共享台账登记了TESTCONTAINERS_RYUK_IMAGE/TESTCONTAINERS_TINY_IMAGE，构建必须把它们映射到相应环境变量。核心服务之外的辅助镜像也需在共享环境中集中管理，不能由本课偷偷升级。

XA测试使用两个实验MySQL root账号以读取XA RECOVER，只在容器内实验数据库上使用。它不授予真实业务库权限。准备事务可能持锁；测试失败时优先根据临时目录决策文件恢复，最后由容器销毁清理全部隔离数据，不能把清理脚本指向生产。

## 独立归档与Academy

仓库工程直接从`../../infra/versions.env`读取共享台账。独立课程包必须由作者导出脚本复制当时的同一台账到`shared/versions.env`，记录SHA-256，并把此文件列入additional_files；它是同一发布版本的快照，不是第二套手改镜像列表。

当前Academy官方导出会剔除Wrapper脚本和JAR，导入后用Check/Run/Gradle工具窗口；源码仓库CLI与官方ZIP运行入口必须分别验证。独立台账快照需要登记到待导出的作者工程，再执行真正GUI导出，不能仅靠源分发脚本假定官方包完整。

公开标准实现位于src及solutions，学生占位由task-info.yaml的UTF-16 offset/length定义。作者必须执行以下真实GUI动作再发布：预览学习者模式、逐题Check、修改后Reset、导出Academy课程包、从干净目录重新导入、重跑实际服务课。静态YAML解析和普通源码ZIP不能替代这些门禁。

全部源代码、调用者、测试、proto生成代码与标准答案均可见。上游生成代码的英文注释标为第三方生成内容，作者自行编写的教学正文/标题/注释使用中文。不要手工翻译或修改生成代码，再生时由固定编译器生成。
