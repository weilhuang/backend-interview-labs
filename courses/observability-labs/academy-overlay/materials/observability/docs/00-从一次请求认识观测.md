# C12 从一次结账请求认识可观测性

这是 V2 教学候选。2026-10-02 的本地完整 JDK21 验证已通过 Java 编译、公开测试和真实回环 HTTP；新 Actions 与原生 IDE 验收仍为 NOT_RUN。先学会读证据，再配置工具；不要求你已经会 Kubernetes、ELK 或 OpenTelemetry。前端、HTTP 服务和测试调用方均已提供。

## 先知道这 12 个词

- **请求**：浏览器问服务器做一件事。这里点一次按钮，发送一次 `POST /checkout`
- **日志（logs）**：发生了什么事件的明细。例如某次库存查询返回 503。JSON 是带字段的记录，不是“看起来像 JSON”的拼接字符串
- **指标（metrics）**：一段时间内发生了多少、分布如何。例如 30 秒内 100 次请求、其中 3 次失败。指标适合总体趋势，不适合保存每个用户的故事
- **链路（trace）**：一次跨服务操作的因果关系。trace ID 关联整条链；span 是其中一个有开始和结束的操作
- **剖析（profiles）**：对程序运行位置采样，回答 CPU 花在哪、内存在哪里分配、线程在哪里等待。长 span 不等于 CPU 忙；此切片尚未采集 profile
- **上下文（context）**：当前操作的关联信息。线程内用 Context/Scope，跨 HTTP 用 traceparent。它不是用户登录状态
- **API**：业务代码调用的“记录一个 span/指标”的接口
- **SDK**：实际创建记录、采样、聚合和导出的实现。只有 API 且没有 SDK，调用通常不会产生可查询的数据
- **Collector（采集器）**：接收、限流/处理、转发遥测的独立进程。它不是默认永久数据库
- **Backend（后端）**：保存并查询证据的系统。本实验候选中 Jaeger 查 trace，Prometheus 查 metrics；ELK 专门练日志
- **SLI（服务水平指标）**：从用户旅程定义的一项测量，例如结账成功请求数 ÷ 合格结账请求数
- **SLO（服务水平目标）**：给 SLI 定义时间窗和目标，例如 30 天成功率达到 99.9%。不是“CPU 永远低于 80%”

## 第二轮才认识的词

Counter 只随事件累计；Gauge 表示当下值，例如正在处理的请求；Histogram 把持续时间按范围计数。Label/attribute 是分组维度。**基数**是不同标签组合的数量，用户 ID 和原始 URL 很容易让它爆炸。Exporter 是导出端，Receiver 是接收端，Processor 是中间处理。OTLP 是 OpenTelemetry 的传输协议；协议接收成功仍不保证后端完整理解每种语义。

## 完整调用链

```text
浏览器已有按钮
  → POST /checkout（checkout 进程 18081）
    → TelemetryFilter 建 SERVER span，保存上下文
      → CheckoutController 校验商品与场景
        → 建 CLIENT span → 注入 traceparent
          → GET /inventory/{sku}（inventory 进程 18082）
            → 提取 traceparent → 建库存 SERVER span → 返回库存结果
        ← 结束 CLIENT span
    ← 返回 HTTP 状态；记录一次指标和安全 JSON 事件；结束 SERVER span
  ← 页面只显示这次真实 HTTP 结果及 X-Trace-Id

两个 SDK -- OTLP/HTTP --> Collector
  ├─ traces -- OTLP/gRPC --> Jaeger（按 trace ID 查询）
  └─ metrics --> Prometheus exporter -- scrape --> Prometheus
独立日志练习：业务 NDJSON 文件 → Logstash → Elasticsearch → Kibana
```

本草稿使用上方课程内ASCII调用链。另保留[可编辑DOT图源](call-chain.dot)，本轮未生成渲染图片。SDK内存exporter不等于真实Collector。

## 三个小检查点

1. C12-01：只补 `SafeEvents.encode`。先运行一条固定输入，再证明 token/cookie/CRLF 不进入日志
2. C12-03：只补 `RequestMetrics.observe`。先看 3 个已知耗时，再解释非累积 OTEL 桶和累积 Prometheus 桶
3. C12-05：只补 `TraceBridge.extract`。先连好两个 span，再跑两台真实回环 HTTP 服务

每一步只引入最多两个核心新概念。Collector、ELK、SkyWalking 分开学，不能一次加三个 agent 再猜重复数据来自哪里。
