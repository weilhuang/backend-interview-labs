订单与库存实验工作台

从一次请求走到数据库事实、消息确认和配送读模型。每个数字来自真实后端；你只需要实现后端课程中的学习区

创建与重试订单

默认商品 book，初始库存 20。相同请求号代表同一次业务意图，网络超时后请保留它

按这个顺序观察

  1. 提交一次，库存下降，待发事件增加
  2. 用原号再提交，库存不会重复下降
  3. 修改数量保留原号，得到 409 冲突
  4. 执行重放，配送读模型追平
  5. 取消订单，再次重放；旧事件不能恢复订单
这里的可靠性边界

Kafka 和 RPC 都可能重复或返回结果未知。数据库唯一身份、事务和接收端 inbox 一起保护业务；Kafka 的生产者幂等不等于跨数据库“恰好一次”。

缓存条目TTL是5秒；旧读晚回填可能延长相对数据库提交的陈旧窗口。审计与强一致查询直接读 MySQL。没有真实支付、个人信息或生产权限。
