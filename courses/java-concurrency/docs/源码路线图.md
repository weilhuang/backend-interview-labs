# OpenJDK21真实源码路线图

固定tag jdk-21+35，解引用commit为890adb6410dab4606a4f26a942aed02fb2f55387。已通过官方仓库git ls-remote核对。所有链接、符号与原始文件文本已静态核验；源码下载的SHA-256记录在作者source-audit.json，原始文件仅留本地build不重新分发。

运行基线是完整JDK21，具体补丁版本必须附java -version；GA源码和21u运行二进制可能有差异。以下是静态导读，不是捏造的动态断点证据。

## 1. 发布、原子性与规范的边界

[AtomicInteger](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/atomic/AtomicInteger.java)：incrementAndGet把单次读改写委托给Unsafe原子更新，返回值还包含加一。对照源码中get、set、compareAndSet的访问方式，不把普通value++等同为原子更新。发布推理必须参考[JLS21线程与锁](https://docs.oracle.com/javase/specs/jls/se21/html/jls-17.html)：源码能展示实现选择，不能取代语言内存模型规范。

断点问题：在哪一行取得唯一序号？如果改为getAndIncrement，只改变可见返回值还是破坏计数原子性？为什么我们的负例测试两者有区别？

## 2. 中断与完成信号

[Thread](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/lang/Thread.java)中的interrupt按目标线程执行上下文处理信号，而不是跳进用户代码抛任意异常。isInterrupted读取，interrupted检查当前线程且清除。CountDownLatch把“清理完成”变成跨线程可见事件；别把线程开始等待、Future取消、业务资源释放混成一个时间点。

断点问题：InterruptedException在哪个阻塞API边界出现？catch后标记是什么？cleanup的写入经过哪个释放/获取路径给调用者可见？

## 3. 条件等待与两种队列

[ArrayBlockingQueue](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/ArrayBlockingQueue.java)：put与take在lockInterruptibly后循环await，修改索引/count，再唤醒互补条件。明确生产者等待容量、消费者等待数据。本题新增排空式close，与JDK原类不同。

[ConditionObject](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/locks/AbstractQueuedSynchronizer.java)：enableWait把等待节点接到条件队列并释放同步状态。signal使节点具备同步争抢资格，线程必须重新获得锁才能离开await。把“通知”画成“立即得到锁”会误导实现。

## 4. AQS21与ReentrantLock的真实获取/释放

```text
ReentrantLock.lock
    -> Sync.lock
       -> initialTryLock（非公平/公平与重入的快速分支）
       -> AQS.acquire
          -> tryAcquire
          -> 排队、停放、被唤醒后重试

unlock -> AQS.release -> Sync.tryRelease
       -> 重入数归零时清除owner -> signalNext
```

[ReentrantLock](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/locks/ReentrantLock.java)：非持有者unlock要失败；重入只释放一次不代表锁完全可用。FairSync的前驱检查和nonfair初次抢占路径需要分别阅读。tryLock无参的公平性约定不能直接等同lock。

[AQS](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/locks/AbstractQueuedSynchronizer.java)：21的acquire统一内部路径处理共享、独占、中断与超时标志；共享成功后signalNextIfShared继续传播。OneShotGate只定义state的语义，没有自己实现队列。记录取消节点如何脱离/被清扫、为何唤醒后要重试，不背旧版教程的字段名。

CountDownLatch是状态减到0后所有等待者通过；Semaphore是扣许可和归还许可，可反复使用；ReentrantLock还追踪所有者/重入。框架相同不表示业务状态机相同。

## 5. CAS、ABA、条带与并发Map

[AtomicStampedReference](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/atomic/AtomicStampedReference.java)比较引用身份与stamp，构造新Pair再casPair；不是先写值再写版本。我们用两个快照字段保存同一原子读取结果。

[LongAdder](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/atomic/LongAdder.java)的add尝试base或cells，竞争升级到[Striped64.longAccumulate](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/atomic/Striped64.java)。sum累计当前可见单元；它不暂停所有写者，因此边读边写不能当事务快照。

[ConcurrentHashMap.computeIfAbsent](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/ConcurrentHashMap.java)：空槽、正在迁移、已存在桶是不同分支；回调必须短，不要求/不允许推导全Map互斥。结合“map中计数器被删除后旧引用继续增长”的反例，界定单方法原子与业务生命周期。

## 6. 线程池execute与submit的两条观察链

[ThreadPoolExecutor.execute](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/ThreadPoolExecutor.java)先尝试核心worker，再offer并复查运行状态，再尝试非核心worker，最后reject。队列offer成功后还复查是为了处理与shutdown交错。runWorker围绕task执行钩子、异常处理与worker退出；getTask受池状态、线程数和超时影响。

[AbstractExecutorService.submit](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/AbstractExecutorService.java)创建RunnableFuture，再交给execute；[FutureTask.run](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/FutureTask.java)把业务异常保存给get。监控只看线程uncaught异常可能漏掉submit故障。

## 7. 完成竞态、超时与上下文

[CompletableFuture](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/CompletableFuture.java)的result更新决定哪个竞争完成获胜。读uniWhenComplete/biApplyStage与postComplete：回调执行线程与依赖图会影响阻塞传播。cancel的mayInterruptIfRunning在该实现并不用来控制底层线程。orTimeout与本课Timer的作用一样需要区分结果期限和外部副作用生命周期。

[ThreadLocal](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/lang/ThreadLocal.java)：remove与过期项清理作用于当前线程的Map。弱key不是立即清理value的保证；ThreadLocal不是跨任务自动传播系统。断点要显示同一个复用线程在前后请求中的值。

## 8. 虚拟线程的调度和受限资源

[VirtualThread](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/lang/VirtualThread.java)的runContinuation/mount/unmount/park/unpark区分任务线程与carrier。onPinned在内部VThreadContinuation中，是21固定源码的一部分，不应把后来版本变化压进本图。

[ThreadPerTaskExecutor](https://github.com/openjdk/jdk/blob/890adb6410dab4606a4f26a942aed02fb2f55387/src/java.base/share/classes/java/util/concurrent/ThreadPerTaskExecutor.java)每任务创建线程；线程轻量并不使等待队列、请求体内存或数据库连接无限。查看[JEP444](https://openjdk.org/jeps/444)与实际JFR记录，并写明没有观察到pinning的原因可能不止一个。
